# USAGE-AGGREGATION-001 — privacy-safe local usage baseline

## Простыми словами

Команда строит воспроизводимый технический baseline по локальным JSONL-журналам
Codex. Она показывает только агрегаты токенов, вызовов, контекста и времени,
отдельно для основного потока и субагентов. Содержимое сообщений, аргументы
инструментов, пути журналов, идентификаторы сессий и предположительная денежная
стоимость в результат не попадают.

## Нормативный контракт

- Идентификатор: `USAGE-AGGREGATION-001`.
- Пользователь: владелец процесса разработки FMonitor.
- Предусловие: пользователь передаёт каталог или отдельный UTF-8 JSONL-файл,
  доступный только для чтения. Каждый файл рассматривается как одна локальная
  сессия; роль определяется только по наблюдаемому
  `session_meta.payload.thread_source`: `subagent` означает субагента, `user` и
  `chatgpt_handoff` — основной поток, прочие и отсутствующие значения —
  `unknown`.
- Действие: `python3 tools/usage/aggregate.py --input PATH [--pretty]`.
- Наблюдаемый результат: stdout содержит один JSON-объект с версией формата,
  общими агрегатами и одинаковыми агрегатами `main`/`subagents`/`unknown`:
  количество сессий и модельных вызовов; input/cached/cache-write/output/reasoning
  tokens; число вызовов инструментов; завершённые turn и их суммарное/среднее
  время; максимум и среднее входного контекста на модельный вызов; известное
  окно контекста и максимальная доля его заполнения, вычисленная для каждой пары
  usage/окно, известной в момент записи. Legacy-снимок без валидного
  `last_token_usage` не создаёт вымышленный context sample. Reasoning входит в output и
  не прибавляется к total повторно.
- Новые `token_usage_record` считаются один раз по уникальному `response_id` из
  поля `usage`. Накопительные `turn_token_usage` и `thread_token_usage` не
  суммируются. При наличии хотя бы одной новой валидной записи legacy-снимки той
  же сессии в токены и вызовы не добавляются. Если новых записей нет, legacy `token_count`
  считается по уникальным монотонным снимкам `total_token_usage`, а итоговые
  токены равны последнему значению каждого монотонного сегмента, не сумме
  снимков. Уменьшение любого cumulative counter начинает новый сегмент,
  увеличивает `legacy_counter_resets` и помечает результат `incomplete=true`,
  поскольку часть использования между наблюдениями могла быть потеряна.
- `model_calls_basis` различает точное число уникальных response IDs
  (`response_ids`) и оценку по различным cumulative snapshots
  (`legacy_distinct_snapshots`); общий mixed результат помечается `mixed`.
  Response IDs доказывают число уникальных записанных ответов, но не полноту всех
  запросов к провайдеру.
- Вызовы инструментов считаются по уникальному `call_id`/`id` у
  `response_item` типов `function_call` и `custom_tool_call`. Выбирается первый
  непустой строковый идентификатор: отсутствующий, `null` или пустой `call_id`
  не скрывает валидный `id`.
- Повторно записанные response, tool call и завершение turn считаются один раз.
- stderr пуст при успехе. Результат и ошибки не содержат строки из message,
  content, input, output, arguments, summary, encrypted content, пути входных
  файлов или session/turn/response identifiers.
- Пустой каталог допустим и даёт нулевые агрегаты. Повреждённые строки и usage с
  отсутствующими обязательными `input_tokens`/`output_tokens`, отрицательными
  либо нецелыми counters пропускаются; их количества сообщаются
  только числами `skipped_lines` и `skipped_usage_records`.
  Наличие пропущенного usage помечает затронутый агрегат `incomplete=true`.
  Если валидная современная запись не содержит `total_tokens`, итог выводится как
  `input_tokens + output_tokens`. Известный per-call input остаётся context sample
  и без окна; неизвестной в таком случае остаётся только utilization.
  Недоступный input, недоступный дочерний файл либо ошибка обхода каталога
  завершают команду с кодом 2 и стабильной общей причиной без отражения
  переданного или дочернего пути и без traceback. Каталог не считается пустым,
  если его содержимое невозможно проверить.
- Денежная стоимость и quota не вычисляются: `billing.available=false` и причина
  сообщает, что локальные журналы не содержат проверенной тарифной разбивки.
- Команда не изменяет входные файлы и не создаёт файлы рядом с ними.

## Независимый пример

Основная сессия содержит два разных response usage: `(100 input, 80 cached,
10 output, 4 reasoning)` и `(140, 120, 20, 8)`, а также дубликат первой записи.
Итог основной сессии: 2 вызова, 240 input, 200 cached, 30 output, 12 reasoning.

Legacy-сессия субагента содержит cumulative snapshots 100, 180, 180 input.
Итог: 2 вызова и 180 input, а не 460.
