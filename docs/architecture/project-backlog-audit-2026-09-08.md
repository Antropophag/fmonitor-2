## Решение о следующем приоритете

Следующей рекомендована **[#46 — безопасный перевыпуск приглашения](https://github.com/Antropophag/fmonitor-2/issues/46)**.

Это новое конкретное замечание владельца: после ухода со страницы он не может
пригласить уже созданного пользователя через интерфейс. Оно непосредственно
мешает ручному тесту сотрудниками, а перенос пользователей ранее исключён:
владелец приглашает их сам. Более общий ADR #32 не является необходимым
предшественником восстановления этого действия.

Основание теперь сильнее предположения по issue:

- [HTTP wrapper](../../app/PilotHttp/PilotUserAccessHttpHandler.php) записывает
  URL в `fm2_invitation_flash` и удаляет его после первого успешного показа
  (строки 34–35); допустимые маршруты не содержат перевыпуска (строка 38).
- [Каталог пользователей](../../app/PilotHttp/MariaDbPilotUserDirectory.php)
  отклоняет повторный `inviteUser` для существующего email и сохраняет только
  hash токена. Повторное создание пользователя не является решением.
- [Pilot CLI](../../rapid-pilot/issue-invitation.php) уже содержит транзакционный
  отзыв старых неиспользованных приглашений и выдачу нового. Его не следует
  копировать ещё раз в HTTP или предлагать владельцу как постоянной ручной обход.

**Ограниченный результат #46:** администратор возвращается к приглашённому
пользователю, видит статус и перевыпускает ссылку; новая ссылка активирует ту же
учётную запись, старая не работает, роли и история сохраняются. Только серверно
авторизованный администратор; одновременные активация и перевыпуск не дают
противоречивого состояния. Исходный токен не требуется восстанавливать из hash
или хранить открытым текстом.

**Архитектурный критерий:** операция приглашений получает одного прикладного
владельца. HTTP и оставленный при необходимости CLI вызывают его; заменённая
самостоятельная запись из pilot-скрипта удаляется. Это ограниченный срез #24,
а не повод перенести весь доступ/сессии или всю структуру каталогов. Возможность
переиспользования CLI подтверждена кодом, но его текущая реализация не объявлена
готовой production-службой: отдельно нужны актор/аудит, авторизация и согласование
конкурентного исполнения с активацией.
