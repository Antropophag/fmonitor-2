# Обязательные входы однообъектного распоряжения по примеру № 12-Р

Дата исследования: `2026-08-27`.

## Источник и границы вывода

Первичный источник — подписанный скан [`Распоряжение от 10.03.2026 № 12-Р.pdf`](../../fmonitor/docs/Распоряжение%20от%2010.03.2026%20№%2012-Р.pdf), 33 PDF-страницы: основной текст на PDF-страницах 1–2 и приложение «Перечень монтажников лифтового оборудования, объектов и производителей работ» на PDF-страницах 3–33 (внутренняя нумерация приложения 1–31).

Источник является многообъектным примером. Ниже за обязательный вход однообъектной версии принимается реквизит, который образует отдельную колонку для каждой строки объекта и/или прямо назван основным текстом как определяемый Перечнем. Это производное описание шаблона; первичный PDF в репозиторий FMonitor 2.0 не переносится.

## Вывод: обязательные поля legacy-объекта монтажа

| Поле документа | Legacy-поле | Почему обязательно | Источник |
|---|---|---|---|
| Адрес объекта | `fm_maintable.ordadr_address` | В каждой строке приложения присутствует колонка «Данные по объекту → Адрес». Основной текст закрепляет монтажников за объектами «по адресам, указанным в Перечне» и требует выполнять работы «по адресам и в сроки, определенные Перечнем». Для документа нужен отображаемый текст адреса, а не только FIAS ID `ordadr`. | PDF-страница 1, пункты 1 и 3; PDF-страница 3, шапка таблицы |
| Подъезд/секция | `fm_maintable.entrance` | В каждой строке приложения присутствует отдельная колонка «подъезд» внутри «Данные по объекту». | PDF-страница 3, шапка таблицы |
| Регистрационный номер объекта/лифта | `fm_maintable.regnumber` | В каждой строке приложения присутствует отдельная колонка «Рег.номер». Это не регистрационный номер распоряжения в 1С ДО. | PDF-страница 3, шапка таблицы |
| Дата начала работ | снимок актуальной плановой даты начала; кандидат legacy-проекции — `fm_maintable.workdatestart` | В каждой строке приложения присутствует колонка «Дата начала работ», а основной текст относит сроки к Перечню. | PDF-страница 1, пункт 3; PDF-страница 3, шапка таблицы |
| Дата завершения работ | снимок актуальной плановой даты окончания: непустая ненулевая `fm_maintable.workdateendadjusted`, иначе `fm_maintable.plan_finish_date`; `workdatefinish` является фактическим завершением и не используется | В каждой строке приложения присутствует колонка «Дата завершения работ», а основной текст относит сроки к Перечню. | PDF-страница 1, пункт 3; PDF-страница 3, шапка таблицы; mapping утверждён в `LEGACY-OBJECT-SNAPSHOT-001` |

Итого минимальный обязательный снимок данных объекта монтажа: **адрес, подъезд/секция, регистрационный номер объекта, дата начала работ и дата завершения работ**.

Названия legacy-колонок подтверждаются существующим field census: [`fmonitor-2-maintainable-field-census.md`](fmonitor-2-maintainable-field-census.md), разделы «Кластеры» и «Полевой census». Сам PDF доказывает обязательность документных значений, но не содержит технических имён колонок.

### Оговорка по датам

Скан называет колонки только «Дата начала работ» и «Дата завершения работ» и сам по себе не определяет алгоритм выбора legacy-дат. Mapping утверждён отдельным исполняемым контрактом [`LEGACY-OBJECT-SNAPSHOT-001`](../specs/LEGACY-OBJECT-SNAPSHOT-001.md): дата начала берётся из `workdatestart`, дата завершения — из непустой ненулевой `workdateendadjusted` с fallback на `plan_finish_date`; фактическая `workdatefinish` не используется как план.

## Состав распоряжения — не поля legacy-объекта монтажа

| Вход | Что выводится | Источник |
|---|---|---|
| Один или несколько выбранных монтажников | Должность, фамилия и инициалы/ФИО, табельный номер | PDF-страница 3, колонки «Должность», «Фамилия, инициалы», «Таб. №» |
| Кадровый снимок монтажника | Статус работника на момент формирования; в примере значение «работа» | PDF-страница 3, колонка «Статус работника (ход работы)» |
| Выбранный инженер строительного контроля | Должность и ФИО | PDF-страница 1, пункт 2; PDF-страница 3, группа «Данные о закрепленном за объектом и монтажниками производителе работ» |

Эти значения должны поступать из выбранного состава, кадрового каталога и каталога пользователей, а не считаться обязательными полями `fm_maintable`. Подготовленная версия должна сохранить их снимок, потому что приложение фиксирует конкретные ФИО, должности, табельные номера и статус.

## Системно вычисляемые реквизиты

| Реквизит | Правило, следующее из шаблона/принятой модели | Источник |
|---|---|---|
| Дата распоряжения | Фиксируется системой при подготовке версии; в подписанном примере — 10.03.2026 | PDF-страница 1, шапка; PDF-страница 3, ссылка приложения на распоряжение |
| Номер распоряжения | Реквизит самого документа, а не объекта монтажа; в примере — 12-Р. Для проекта до регистрации может отсутствовать, затем возвращается из 1С ДО | PDF-страница 1, шапка; PDF-страница 3, ссылка приложения |
| Форма организации труда | Вычисляется из выбранного состава: индивидуальная или бригадная; не вводится из legacy-объекта монтажа | PDF-страница 1, пункт 1; PDF-страница 3, колонка «Форма организации труда» |
| Номер строки | Для однообъектного приложения — системный порядковый номер строки | PDF-страница 3, колонка «№ п/п» |
| Размер приложения и пагинация | Формируются рендерером из фактического состава документа | PDF-страница 2, абзац «Приложение к распоряжению»; PDF-страницы 3–33, внутренняя пагинация |

## Статический текст шаблона

К статике относятся фирменная шапка, название и тема распоряжения, преамбула, пункты обязанностей монтажников и производителей работ, поручение о рассылке, название приложения, подписи колонок и наименование должности подписанта. Они не должны становиться полями legacy-объекта монтажа. Основание: PDF-страницы 1–2 и повторяющаяся шапка приложения на PDF-страницах 3–33.

ФИО подписанта и конкретные ссылки на прекращаемые предыдущие распоряжения (PDF-страница 2, пункты 7 и блок подписи) нельзя без отдельного решения считать неизменным текстом однообъектного шаблона: это реквизиты документооборота/версии, но не данные legacy-объекта монтажа.

## Что шаблон не требует от legacy-объекта монтажа

В приложении отсутствуют legacy ID (`fm_maintable.id`), заводской номер лифта (`zavnumber`), УНОМ, округ/район и FIAS ID (`ordadr`). Они могут оставаться техническими идентификаторами и данными карточки, но пример № 12-Р не даёт основания блокировать формирование документа при их отсутствии.
