# Заполнение чек-листов по декларациям

Скрипт доступен как защищённая веб-страница FMonitor и как CLI-команда. Он находит объекты с заполненной декларацией и доводит их чек-листы до 100%. На каждый новый выполненный пункт назначаются все уникальные значения из полей `Монтажник 1–4`. Значение `999999` (`Монтажник не закреплён`, табельный номер `000000` в интерфейсе) считается монтажником.

Уже выполненные пункты и назначенные на них исполнители не изменяются. Время выполнения новых пунктов — фактическое время запуска скрипта; история задним числом не создаётся.

## Запуск через браузер при доступе по FTP

Загрузите на сервер три файла с сохранением каталогов:

- `application/controllers/Checklist_declaration_backfill.php`;
- `application/views/checklist_declaration_backfill/index.php`;
- этот файл документации загружать необязательно.

Войдите в FMonitor пользователем с правом изменения чек-листа и откройте:

```text
https://fmonitor.shlz.ru/integration/declaration-checklists
```

Страница сначала выполняет только dry-run и показывает объекты, пункты и монтажников. Кнопка «Применить с backup» запускает транзакцию и выводит `RUN_ID`. Вернитесь на страницу кнопкой браузера или откройте URL повторно: применённый запуск появится в таблице, где для него доступна кнопка `Rollback`.

## Проверка без изменений через CLI

Из корня приложения:

```bash
php index.php checklist_declaration_backfill dry_run
```

Команда выведет количество объектов, недостающих пунктов и создаваемых назначений, а затем список регномеров и монтажников. Если найдётся объект без монтажников, неизвестный табельный номер или дубль пункта чек-листа, команда завершится ошибкой до изменения данных.

## Применение

Сначала узнайте ID пользователя, от имени которого нужно записать изменения. Затем выполните:

```bash
php index.php checklist_declaration_backfill apply USER_ID YES
```

Весь запуск выполняется одной транзакцией. Перед изменениями создаются служебные таблицы со снимком старых строк. После успеха команда напечатает `RUN_ID`; его нужно сохранить.

Сразу после применения повторите `dry_run`. Ожидаемый результат: `Объектов: 0` и `Недостающих пунктов: 0`.

## Rollback

Для полного отката конкретного запуска:

```bash
php index.php checklist_declaration_backfill rollback RUN_ID YES
```

Rollback удаляет созданные этим запуском отметки, назначения и записи журналов, а существовавшие строки со значением `0` и их назначения восстанавливает из снимка. Если после запуска кто-либо успел вручную изменить затронутый пункт, rollback остановится без частичного отката.

После проверки выгрузки backup-таблицы удалять не нужно: они являются аудитом и позволяют выполнить поздний откат. Повторно применить тот же набор изменений безопасно — завершённые пункты пропускаются.
