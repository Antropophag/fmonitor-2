# Данные ручного пилота —2026-09-07

## Режим

Стартовая загрузка объектов и технических характеристик — разовый срез.
Кадровый каталог Bitrix — отдельная первичная загрузка и последующее плановое
обновление; не двусторонняя синхронизация со старым FMonitor. Новые process facts
пилота не затираются повторным импортом. Реальный импорт/Bitrix call в этой сессии
ещё не выполнялся и остаётся отдельным разрешённым operational действием.

## Пользователей НЕ переносить

Владелец явно уточнил: **«пользователей выкидывай, сам отправлю приглашения кому нужно»**.
Это исключает перенос пользователей/назначений из старой системы и массовое
создание аккаунтов для стенда. Первичный административный доступ владельца
нужен для приглашений; роли и их permissions настраиваются в новом приложении.
Остальные пользователи создаются приглашениями владельца. Старые пароли и сессии
не переносятся. Указание не означает удаления существующих аккаунтов/данных
сохраняемого preview и не разрешает рассылку приглашений агентом.
Synthetic accounts в изолированных automated smoke fixtures — только тестовые
данные, не аккаунты передаваемого владельцу стенда.

## Отбор объектов — дополнительное решение владельца

Владелец уточнил: **«открытые дела мы не переносим, переносим только те объекты,
по которым еще не было движения чек-листов»**.

Переносить только объекты без открытого дела/фактического начала и без какой-либо
истории checklist activity. Проверять сохранённую историю операций/атрибуции,
а не только текущий процент: прежние отметки, включая впоследствии снятые или
исправленные, исключают объект. Не трактовать отсутствие доступа к истории как
нулевую историю; такой объект пропускается с причиной для проверки.
Создаётся новое unopened дело; прежние opening/checklist/inspection facts не
импортируются. Последующим решением владельца ограничение по плановой дате полностью снято:
просроченная, отсутствующая или плохо заполненная плановая дата не исключает объект. До записи выполнять dry-run с количеством допущенных/исключённых
объектов и основаниями исключения. Реальный импорт пока не запускался.

## Стартовые данные

- Ещё не начатые объекты без checklist activity, независимо от плана: исходный ID, адрес,
  подъезд, регномер, плановые даты начала/окончания и скорректированный срок.
- Технические поля текущего importer: floors, weight, speed, pittype, pitmaterial, paired.
- Версия шаблона чек-листа: разделы, пункты, порядок, веса; у дела immutable snapshot.
- Монтажники: отдельный кадровый каталог, не пользователи; ID Bitrix, табельный
  номер, ФИО, должность, текущий статус, scope подразделений, известная дата приёма.

Исторические распоряжения/PDF/checklist/payment facts не переносятся по ранее
утверждённому fresh-launch решению. Старый responsstroicontrol не создаёт нового
назначения: инженер выбирается из локальных приглашённых пользователей и
подтверждается в составе. Коммерческие реквизиты/суммы требуют отдельной сверки;
текущий базовый importer не является полной копией старой карточки.
