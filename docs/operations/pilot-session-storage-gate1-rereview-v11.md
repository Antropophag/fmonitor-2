## Conclusion

The v8 amendment closes the exact gap without creating a production selector or
a self-attesting test protocol. It adds one narrow CLI application boundary,
four exact dependencies and no session-owner authority:

- `PilotSessionStorageInspection::inspect(config, filesystem)` is implemented
  by the existing real inspector;
- `PilotSessionInspectorCliArguments::values()` supplies only arguments after
  the executable name;
- `PilotSessionInspectorCliOutput` has separate stdout/stderr byte sinks;
- `PilotSessionInspectorCliApplication` receives inspection, filesystem,
  arguments and output, and returns the exact process exit integer.

The public signatures are syntactically valid PHP, fully typed and have no
optional/default parameter. The application can now be tested
deterministically at the same mapping boundary:

- invalid syntax/config is rejected before inspection/filesystem access, writes
  the exact usage line once to stderr, and returns `64`;
- real inspector `UNAVAILABLE` writes the redacted unavailable line once and
  returns `65`;
- a verifier-owned inspection implementation may only throw; the application
  redacts its class/message/trace, writes no stdout, writes the unavailable line
  once to stderr and returns `70`;
- only the real inspector can create a successful inspection result; success
  calls it once, writes canonical JSON plus one LF once to stdout, writes no
  stderr and returns `0`.

The throwing test implementation cannot fabricate success because
`PilotSessionInspectionResult` construction remains restricted to exact real
inspector call sites and the architecture ratchet continues to forbid all other
factory calls. Supplying a filesystem wrapper drives real-inspector exit `65`;
supplying a throwing inspection drives only exit `70`. Neither path can claim
session, cookie, authentication, event or material success.

Production composition is unambiguous: the bin executable always binds the real
inspector, native read-only primitives, `array_slice($argv, 1)` and direct
stdout/stderr. No environment, request, Compose or argv value selects injected
dependencies; argv is data only. There is no alternate production bootstrap.

All v7 storage semantics remain intact: configuration/path ownership, atomic
write, regenerate/destroy crash regions, locks and monotonic timeout, bounded
GC, event/fault API, LocalAuth/UserAccess response buffering and protocol,
route priority, canonical read-only inspection, Compose restart proof and
anti-self-attestation restrictions are unchanged. The amendment changes only
the inspector CLI composition/testability boundary and the lifecycle text that
requires fresh v8 approval.
