# Подтверждённый оригинал → карточка → открытие работ

Дата: 2026-09-07. Новое прямое уточнение владельца в режиме стабилизации.

> У тебя какой-то лишний переход во флоу, мы загружаем оригинал, на той же странице подтверждаем что все ок и дальше редирект в карточку где в текущем действии уже открытие работ

## Продуктовое решение

Загрузка файла и подтверждение соответствия оригинала выполняются на одной
странице. После принятия оригинала пользователь возвращается в карточку объекта.
В текущем действии карточки для уполномоченного сотрудника находится открытие
работ с фактической датой. Отдельного пользовательского шага/кнопки «Применить
состав» и промежуточной страницы execution быть не должно.

Открытие не происходит автоматически при загрузке. Загрузчик и сотрудник,
который открывает работы, могут быть разными людьми. Фактическая дата открытия,
серверные полномочия, оригинал/состав, кадровая допустимость и append-only история
сохраняют обязательность. Шесть канонических UI-статусов сохраняются.

Это уточнение отменяет старое требование отдельного ручного применения состава
в пользовательском маршруте; оно не отменяет доказуемый application fact как
основание opening/checklist и не разрешает мутации из GET/renderer.

## Выбранная техническая реализация

Внутреннее применение точного подтверждённого оригинала выполняется owning
application module при явной команде открытия, атомарно с opening. Это выбор
реализации, а не дополнительное процитированное решение владельца.

Один новый публичный compound opening seam проверяет `installation.open` и
действующие роли открытия, exact original revision/sequence, дату, состав,
кадровую допустимость и checklist template. При отсутствии application создаёт
его, при необходимости до открытия применяет исправленный original, затем
открывает дело в одной транзакции. Ошибка не оставляет частично выполненное
применение/открытие. Уже сохранённые application facts и standalone API остаются;
standalone apply не получает расширенных полномочий.

HTTP вызывает этот seam; card read только показывает accepted original,
выбранный состав и правильный следующий шаг. Новых ролей или разрешений
пользователям автоматически не назначают. Original upload/correction остаётся
собственным приложением с прежним хранением bytes/history и не открывает работы.

Изменение входит в уже присланное замечание о лишнем шаге и выполняется до
VERIFY_OK; остальные новые улучшения остаются в backlog.
