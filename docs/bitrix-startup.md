# Запуск стенда с legacy-данными и Bitrix

Скопируйте `.env.example` в `.env`, заполните runtime, legacy DB и Bitrix
параметры, затем выполните `make up-with-data`. Команда поднимает Yii2 runtime,
импортирует legacy-данные существующим owner, после чего запускает существующий
owner кадровой синхронизации. Ready объявляется только после успеха всех этапов.
Нужны Git, Make, Docker
с Compose v2 и стандартная оболочка. PHP и соседний `../fmonitor` не нужны.

## Настройка

Задайте уникальные пароли, read-only доступ к legacy DB и параметры Bitrix:

```dotenv
FMONITOR_BITRIX_WEBHOOK_URL='https://example.invalid/rest/1/replace_me/'
FMONITOR_BITRIX_DEPARTMENT_IDS_JSON='[101,102]'
```

Это вымышленные значения: замените URL на выданный вам HTTPS-вебхук с доступом
к чтению каталога сотрудников, а числа — на нужные ID отделов. Не копируйте
вебхук в команды терминала, Git или сообщения об ошибках.

Каждый параметр указывается ровно один раз, на одной строке. Поддерживаются
значения без кавычек, в одинарных или двойных кавычках; кавычки снимаются,
подстановки переменных и escape-последовательности не поддерживаются.
Пишите комментарии отдельными строками. Список отделов — JSON-массив
положительных уникальных целых ID, например `[101,102]`.

Для отдельных повторных операций доступны `make import-legacy` и
`make sync-workforce`; каждая команда проверяет только свой набор настроек.

Пилот открывается на порту `FMONITOR_HTTP_PORT` из `.env`; шаблон использует
<http://127.0.0.1:8093/>. Worker синхронизирует каталог
при старте, затем по существующему часовому расписанию. Готовность worker
публикуется после успешной синхронизации; недоступный Bitrix не выдаётся за
успешно запущенную синхронизацию.

## Ошибки и изменение настроек

Если `.env` отсутствует, вебхук некорректен или список отделов пуст/неверен,
запуск прекращается до Docker, сети или DB effects. Сообщение указывает
на настройки в `.env`, не раскрывая значений. Исправьте файл и повторите
нужную команду. Старый приватный файл при неудачной подготовке не заменяется
и не используется как обход ошибки.

Для смены legacy или Bitrix параметров отредактируйте существующий `.env` и
повторите соответствующую команду либо `make up-with-data`: consumer получит
новый полный snapshot.
Не перезаписывайте `.env` шаблоном при обновлении: make reset не нужен,
данные и история сохраняются. `make down` останавливает стенд
с сохранением volumes; следующий `make up` использует текущие настройки.

Подготовка локально читает `.env` без shell evaluation и атомарно записывает
внутренние `.local/legacy-source.env` и `.local/bitrix-workforce.json`
(каталог `0700`, файлы `0600`). Они создаются автоматически; оператор не
создаёт и не редактирует их вручную. Consumers получают read-only mounts, без
пароля или вебхука в environment контейнера. `.env` и
`.local/` исключены из Git и контекста сборки; образ не содержит секретов.

Параметры `FMONITOR_SOURCE_*` нужны только для отдельного импорта исходных
объектов и не являются настройками кадровой синхронизации Bitrix.
