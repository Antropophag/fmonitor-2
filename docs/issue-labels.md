# Labels открытого backlog

Эта схема помогает вручную читать и фильтровать открытые GitHub issues. Ни один
label не является разрешением агенту начать работу, выполнить merge/deployment или
пропустить действующий delivery lifecycle. Текущую очередь и полномочия по-прежнему
задают владелец, `docs/operations/current-delivery-goal.md` и подготовленный
delivery package; автоматический запуск по этим labels запрещён.

## Схема

У каждой открытой issue ровно один основной тип:

- `type:product` — пользовательская функция, пользовательская ошибка, UX или
  бизнес-правило;
- `type:tech-debt` — технический долг приложения без самостоятельного нового
  пользовательского результата;
- `type:harness` — harness, CI, Quality Graph, gates и другие инструменты
  агентской разработки и поставки;
- `type:tracking` — аудит, roadmap, эпик-реестр или учёт нескольких
  самостоятельных остатков.

Исполняемая issue дополнительно имеет ровно одну степень проработки:

- `prep:triage` — актуальная оценка отсутствует или данных недостаточно;
- `prep:needs-work` — найден конкретный пробел в решениях, границах, приёмке или
  декомпозиции; причина кратко указана в issue;
- `prep:ready` — постановка достаточно определена, чтобы начать реализацию по
  действующему процессу.

У `type:tracking` нет `prep:*`: готовность оценивается у отдельных исполняемых
задач. `prep:ready` требует понятных проблемы и результата, проверяемой приёмки,
ограниченного scope и non-goals, принятых продуктовых решений, названных
зависимостей и сверенного с актуальным source непоставленного остатка. Он не
является `agent-ready` и не заменяет актуальную проверку перед выдачей.

Необязательные независимые ограничения ставятся только по положительному
актуальному основанию:

- `status:blocked` — подтверждённое препятствие или зависимость с пояснением;
- `status:deferred` — актуальное решение владельца отложить работу;
- `status:in-progress` — актуальное подтверждение текущего исполнения.

При существенном пробеле `prep:ready` снимают, ставят `prep:needs-work` и
поясняют причину. При устаревшей или непроверяемой оценке используют
`prep:triage`. После начала, остановки или снятия зависимости status пересматривают
по фактам; закрытие связанной issue само по себе ещё не доказывает поставку.
Сторонние и `quality-graph:*` labels эта схема не заменяет и не изменяет.

## Фильтры

- Продукт: `is:issue is:open label:"type:product"`
- Технический долг: `is:issue is:open label:"type:tech-debt"`
- Harness: `is:issue is:open label:"type:harness"`
- Требуют проработки: `is:issue is:open label:"prep:needs-work"`
- Реестры: `is:issue is:open label:"type:tracking"`
- Готовые продуктовые кандидаты без отмеченных ограничений:
  `is:issue is:open label:"type:product" label:"prep:ready" -label:"status:blocked" -label:"status:deferred" -label:"status:in-progress"`

Последний фильтр показывает только кандидатов для ручной выдачи после актуальной
проверки; это не автоматически разрешённая очередь.
