## Findings

- **Traceability and seam — pass.** The regression exercises the section 4 trusted loopback browser composition through the printed production HTTP seam. It does not call `validRequest()`, session internals, or a substitute renderer.
- **Narrow trusted-context acceptance — pass.** The accepted request uses the canonical demo Host, the browser-usable demo session cookie issued for that Host, `Sec-Fetch-Site: same-origin`, and the fresh session-bound CSRF token and revision rendered by the form. Its intentionally incomplete engineer confirmation produces the exact validation PRG back to the form, proving that literal `Origin: null` passed request validation without invoking a process command.
- **Ordinary and noncanonical confinement — pass.** The same literal `Origin: null` must return the exact redacted `403` in an ordinary built-in/router composition, even when that process environment contains `FMONITOR_TRUSTED_REQUEST_HOST`. It must also return `403` for a valid but noncanonical loopback Host on the real demo listener. These cases prevent a global `null`-Origin allowance and preserve the exact canonical Host/nonce trust boundary.
- **Session/CSRF boundary — pass.** Acceptance is demonstrated only with the cookie and fresh CSRF token produced by the canonical form. The existing coordinator contract still consumes and validates the session-bound token after Origin/Fetch checks; the new expectation does not weaken or bypass those assertions. The test refreshes the form after the validation redirect because the accepted request consumes its token, which also makes a fake acceptance before token consumption observable in later flow.
- **Zero mutation — pass.** The accepted canonical request omits required engineer confirmation and therefore can only redirect with validation state. The subsequent refreshed form and successful version-1 preparation prove that no order was created. Ordinary and noncanonical rejections are followed by exact queue-projection equality before any successful command, proving no process fact was appended.
- **Sensitivity and cross-site risk — pass.** An implementation that accepts `Origin: null` outside `trustedDemo()` fails either ordinary or noncanonical assertions. An implementation that broadly trusts inbound Host fails the existing Secure-cookie and matching-attacker-Origin checks. A change that performs the incomplete command instead of validation prevents the following version-1 happy path. No cross-site credential path is introduced by the expected values: the exception remains limited to an exact loopback listener composition with its server-injected nonce and canonical Host, while session, CSRF, Fetch Metadata, body, authorization, and revision checks remain required.
- **Expected-value independence — pass.** The canonical Host, routes, `403` body, PRG target, people and version are literal approved contract values, not copied from private implementation helpers or generated by the implementation under test.
- **Determinism, isolation, and cleanup — pass.** The regression reuses the bounded unique MariaDB database, checkout-specific home, real loopback listener, public projections, and existing `finally` cleanup. The focused RED left no test fixture in the worktree.

No blocking or non-blocking findings.
