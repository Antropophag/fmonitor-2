# ORDER-PREPARE-007 — ошибка формирования документов

- Статус: `APPROVED`
- Версия: `0.1`
- Дата: `2026-08-28`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

## 1. Цель

Дать сотруднику понятный и безопасный результат, если после успешных проверок система не смогла сформировать распоряжение или приложение.

Ошибка генератора документов не должна создавать распоряжение без полного комплекта файлов, назначения или ложное состояние успеха. Пользователь может повторить обычное действие после устранения временной ошибки.

## 2. Предусловия и порядок

- авторизация, обязательный состав, отсутствие актуальной версии, реквизиты объекта и допустимость людей успешно проверены;
- конкурентного изменения нет;
- renderer вызывается один раз для полного комплекта из распоряжения и приложения;
- renderer выбрасывает ошибку до возврата полного комплекта либо возвращает ошибку после частичного внутреннего результата;
- persistence версии, назначений, артефактов и legacy-проекции после ошибки renderer не вызывается.

```text
all approved validations
→ renderer
→ on renderer failure: rejection audit and return
→ persistence is not reached
```

## 3. Наблюдаемый отказ

```text
accepted = false
violations = [
  {
    code: ASSIGNMENT_ORDER_RENDER_FAILED,
    message: "Не удалось сформировать документы распоряжения. Повторите действие позже.",
    field: null
  }
]
```

Ответ не раскрывает имя шаблона, путь к файлу, exception message, stack trace или устройство renderer.

## 4. Состояние и аудит

Монтажное дело остаётся в исходном состоянии `needs_assignment_order`. Не создаются версия распоряжения, назначения, артефакты, хэши, событие успеха, открытие работ, доступ к чек-листу или legacy-проекция.

Добавляется ровно одно событие `assignment_order_prepare_rejected`:

```text
reasonCodes = [ASSIGNMENT_ORDER_RENDER_FAILED]
installerCount = <число нормализованных уникальных входных монтажников>
controlEngineerProvided = true
```

Аудит не содержит идентификаторы и снимки людей, данные объекта, содержимое документов, внутренний текст ошибки, путь, stack trace или конфигурацию renderer. Техническая диагностика может быть записана отдельным инфраструктурным журналом, который не входит в публичную процессную проекцию этого среза.

## 5. Исполняемый пример A

Сотрудник `18` вызывает `prepareAssignmentOrder(4512, [1042], 73, 18)`. Все проверки проходят. Renderer получает утверждённые данные, но завершается ошибкой `template service unavailable` до возврата полного комплекта документов.

Команда возвращает точный отказ раздела 3. Исходная проекция монтажного дела сохраняется; в `events` добавляется только безопасное событие раздела 4. Fixture запрещает любое сохранение успешной версии после вызова renderer.

## 6. Повтор действия

Ошибка не считается успешной или неизвестно завершившейся подготовкой. После восстановления renderer сотрудник может заново нажать «Сформировать распоряжение». Повтор проходит все проверки заново и может создать версию `1`; автоматического скрытого повтора renderer в рамках неудачного вызова нет.

## 7. Не входит

- ошибка persistence после успешного формирования обоих документов;
- таймауты и политика автоматических инфраструктурных повторов;
- очистка временных файлов внутри конкретной реализации renderer;
- недействительный шаблон как отдельная ошибка конфигурации;
- скачивание уже сохранённых документов;
- UI и HTTP.

## 8. Решения и доказательства

- `PRODUCT.md`: каждый факт имеет основание; недопустим частичный документ или ложное состояние процесса.
- `docs/fmonitor-2-primary-spec.md`: при отказе нет частичного результата, возвращается стабильная предметная причина.
- `ORDER-PREPARE-002`: успешная версия существует только с двумя сформированными артефактами и их хэшами.
- `ORDER-PREPARE-006`: конкурентность persistence рассматривается отдельно и не смешивается с ошибкой renderer.
