# OTIZ-EXCEL-CALCULATION-001

## Простыми словами

Первый implementation slice №66 создаёт чистую версию Excel-арифметики и распределения копеек. Следующие slices подключают её к документам, публикации, выплатам и Yii2. Отдельный calculator не объявляет №66 завершённым.

## Contract

Public seam `FMonitor2\Otiz\PremiumCalculationV2::calculate(array $operands, array $paymentEvidence, array $exclusions=[]): array`; `allocate(int $poolCents,array $participants): array`. No database, clock, filesystem, actor or permissions: callers own authorization and evidence collection. Existing `PremiumCalculation` v1 remains unchanged for explicit historic callers. Version constant `premium-calculation-v2-excel`, allocation version `largest-remainder-tab-asc-v1` are returned as `calculationVersion` and `allocationVersion`.

Inputs use the v1 source envelope `{value,effectiveDate,source:{label,locator,contentSha256}}` for reportDate, premiumCents, shaftBp, progressBp, deadlineDate, completionDate. Each exact ISO date and lowercase SHA256 is required; completion value alone may be null. premium integer0..1e12, shaft integer0..20000, progress integer0..10000. Invalid/missing evidence throws InvalidArgumentException, with no external facts. No float inputs. Input arrays remain unmodified and are retained as operandEvidence/paymentEvidence.

Payment evidence is `{closures:list,actualPayouts:list}` as v1; the v2 closures represent ONLY net confirmed paid money, never drafts or discipline/deadline holds. Each row has signed integer amountCents (absolute <=1e12), closedOn and source. actualPayouts use paidOn and remain informational. Negative aggregate paid values or aggregate beyond1e12 are rejected. Caller applies report-date selection. Each exclusion has uppercase code, exact effectiveDate, source; exclusions leave computed pool visible but distributableCents=0.

Comparison date = completionDate even after reportDate, else reportDate. daysLate is max(0, calendar date difference), Kss=max(0,10000-100*daysLate). At each money boundary use integer HALF-UP: fund=premium*shaft/10000; progressAmount=fund*progress/10000; remainingBeforePenalty=max(0,progressAmount-paid); deadlinePenalty=remainingBeforePenalty*(10000-Kss)/10000; pool=remainingBeforePenalty-deadlinePenalty. Return top-level daysLate, comparisonDate, kssBp; amounts fundCents, progressAmountCents, paidBeforeCents, remainingBeforePenaltyCents, deadlinePenaltyCents, poolCents, distributableCents, remainingFundCents=max(0,fund-paid). formulaTrace identifies every operation and its result. No draft/no-progress cutoff: same inputs give same result regardless of previous calculations.

Examples (cents): premium49725000/shaft10000/progress10000/paid9360000/9days → fund49725000, progress49725000, remaining40365000, penalty3632850,pool36732150. plan2026-08-08/report2026-08-17/noPTO→9days; plan2026-07-18/PTO2026-07-20→2days; effective certificate deadline2026-08-16/PTO2026-07-28→0days; plan2026-08-10/report2026-08-15/PTO2026-08-20→10days. Boundary days0/1/99/100/101 gives Kss10000/9900/100/0/0. Premium1/shaft15000/progress2500 gives fund2,progress1. Remaining1/Kss5000 gives penalty1,pool0. Premium10000/paid9000/Kss9000→pool900; paid9900→90; paid9990→9. Paid beyond progress gives pool0.

Allocation input participants are list of `{tab:string,weight:int}`; tab nonempty trimmed UTF8 <=120chars, unique, weight1..10000; pool integer0..2e12. Empty participants is allowed only for zero pool, returning[]. Invalid values throw InvalidArgumentException. Return list `{tab,amountCents}` sorted by binary lexicographic tab. Use exact integer quotient/remainder, then assign leftover cents by descending remainder and tab ascending on ties. Return no float money. Pool2 with A weight1/B weight2→A1/B1; pool1 equal weights A/B→A1/B0; input order cannot change output; sum exactly equals pool. Persisted allocationVersion makes tie-break reproducible. Large pool2e12 with three equal weights yields A666666666667/B666666666667/C666666666666.

## Verification scope

Exact formulaTrace is an ordered list: `{step:'fund',resultCents:fund}`, `{step:'progress',resultCents:progressAmount}`, `{step:'deadline',daysLate:days,resultBp:kss}`, `{step:'paid',resultCents:paid}`, `{step:'remaining',resultCents:remainingBeforePenalty}`, `{step:'penalty',resultCents:deadlinePenalty}`, `{step:'pool',resultCents:pool}`. These stable step names identify the formulas defined above. Informational actualPayouts have the same signed amount/date/source validation and nonnegative aggregate<=1e12 as closures; they never change pool. Collections must be lists, every required envelope member is mandatory. Exclusion code grammar is `[A-Z][A-Z0-9_]{2,79}`. Wrong top-level PHP argument types throw TypeError as enforced by the public signature; invalid values inside arrays throw InvalidArgumentException.

Focused public pure-seam tests cover the full contract including invalid inputs, provenance and deterministic allocations; historical v1 regression remains unchanged. Schema, permissions, file storage, concurrency, HTTP and backup are inapplicable to this pure slice, and remain mandatory in the parent change's subsequent integration slices. Root authors contract/tests, independent Gate3 approves RED, separate executor implements, independent Gate5 reviews. Full exact-source CI follows the complete №66 candidate.
