# ORDER-PREPARE-002-F — запрет подготовки после Акта ПТО

- Статус: `WITHDRAWN — не реализовывать в последовательности ORDER-PREPARE-002`
- Версия: `0.1`
- Дата: `2026-08-27`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

## 1. Цель

> Отозвано `2026-08-27`: в непротиворечивом новом процессе Акт ПТО возникает только после распоряжения, открытия и выполнения работ, поэтому не является нормальным предусловием первой подготовки. Сочетание `needs_assignment_order` и даты Акта ПТО возможно только как проблема импортированных legacy-данных и должно рассматриваться отдельным контрактом отбора/качества миграции. Этот документ не разрешает тест или production-реализацию.

Не допустить обычную подготовку распоряжения после того, как по объекту монтажа зафиксирован факт Акта ПТО.

В пилоте факт существует при наличии даты `installationObjectSnapshot.ptoActDate`, источником которой является `fm_maintable.ptoactdate`. Файл акта необязателен и не участвует в решении команды.

## 2. Предусловия

- авторизация и обязательный состав прошли;
- объект монтажа существует, доступен и имеет состояние `needs_assignment_order`, не открыт и не имеет версии распоряжения;
- все пять обязательных реквизитов объекта монтажа заполнены;
- `ptoActDate` заполнена;
- выбран один монтажник и один инженер; их каталоги при этом отказе не вызываются;
- renderer не вызывается, конкурентного изменения нет.

## 3. Нормализация и порядок

Факт Акта ПТО существует, если `ptoActDate` не равна `null` и не является пустой либо пробельной строкой. Формат и календарная корректность непустой даты обеспечиваются LegacyInstallationObject adapter и не входят в срез.

Порядок проверок: авторизация → обязательный состав → полный набор обязательных реквизитов объекта монтажа → наличие даты Акта ПТО → каталоги людей и renderer.

Если одновременно отсутствуют обязательные реквизиты и заполнена дата Акта ПТО, сначала возвращается полный `INSTALLATION_OBJECT_REQUIRED_DATA_MISSING`. Факт Акта ПТО не раскрывается до исправления качества обязательных данных.

## 4. Наблюдаемый отказ

```text
accepted = false
violations = [
  {
    code: ORDER_HAS_PTO_ACT,
    message: "По объекту монтажа уже зафиксирован Акт ПТО. Формирование распоряжения запрещено.",
    field: ptoActDate
  }
]
```

## 5. Состояние и аудит

Версии, назначения и артефакты не создаются; состояние, открытая задача подготовки и закрытые шлюзы работ/чек-листа не меняются. Добавляется одно событие `assignment_order_prepare_rejected`:

```text
reasonCodes = [ORDER_HAS_PTO_ACT]
ptoActPresent = true
installerCount = 1
controlEngineerProvided = true
```

Событие содержит также `installationObjectId`, `actorId`, серверный `occurredAt`, но не сохраняет саму дату Акта ПТО, значения объекта монтажа или персональные данные выбранных людей.

## 6. Исполняемый пример A

```text
installationObjectId = 4512
installerTabIds = [1042]
controlEngineerUserId = 73
actorId = 18
now = 2026-08-27T13:00:00+03:00

address = "Москва, ул. Примерная, д. 10"
entrance = "2"
objectRegistrationNumber = "77-000123"
plannedStartDate = 2026-10-05
plannedFinishDate = 2026-12-20
ptoActDate = 2026-08-25
ptoActFile = null
```

Несмотря на отсутствие файла, ожидается точный `ORDER_HAS_PTO_ACT`. Исходное состояние `needs_assignment_order` сохраняется, добавляется только событие раздела 5 с `occurredAt = 2026-08-27T13:00:00+03:00`. Fixture запрещает каталоги людей и renderer.

## 7. Не входит

- загрузка, обязательность, проверка или скачивание файла Акта ПТО;
- исправление ошибочной даты и история самого акта;
- запрет изменения назначения и открытия работ после Акта ПТО — отдельные команды и срезы;
- остальные отказы состояния, людей, renderer, persistence и конкурентности;
- успешная подготовка, UI и HTTP.
