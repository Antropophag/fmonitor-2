# YII2-SIDEBAR-NAVIGATION-002 — ясная навигация рабочего shell

## Простыми словами

Сайдбар должен выглядеть как часть `shlz-ui`, ясно раскрываться после сворачивания и группировать рабочие разделы по смыслу. Обратная связь остаётся рядом на каждой странице, но больше не притворяется разделом системы.

## Контракт

### A1. Общая структура

Для аутентифицированного пользователя общий Yii shell SHALL выводить единственную навигацию `Основная навигация`. Разрешённые пункты идут в таком порядке групп:

1. `Монтаж`: `Объекты монтажа`, `Стройконтроль`;
2. `Справочники`: `Монтажники`;
3. `ОТиЗ`: пункт `ОТиЗ`;
4. `Администрирование`: `Пользователи`, `Роли`.

Пустая группа SHALL отсутствовать. Состав пунктов по permissions остаётся прежним.

### A2. Иконки

Каждый пункт и оба состояния collapse-control SHALL использовать SVG, поставляемый pinned `shlz-ui`. Inline произвольные path-заглушки запрещены. Если подходящего символа в `shlz-ui` нет, допускается один локальный SVG с теми же `24×24`, fill/stroke, толщиной, linecap/linejoin и оптической массой; причина и сравнение фиксируются в design.

### A3. Сворачивание

На desktop collapse-control SHALL быть видимым и кликабельным в раскрытом и свёрнутом состояниях, иметь `aria-label` соответственно `Свернуть меню`/`Развернуть меню`, различимые chevron-left/chevron-right и target не меньше 44×44 CSS px. Keyboard activation и сохранение состояния остаются рабочими. На mobile нижняя навигация не получает лишний collapse-control.

### A4. Обратная связь

`Обратная связь` MUST NOT быть потомком основной навигации. Общий shell SHALL показывать один фиксированный action-link справа снизу с `aria-label="Обратная связь"`, shlz-ui chat icon, target не меньше 44×44 и URL `/pilot/feedback?from=<current-path>`. Он не перекрывает нижнюю mobile navigation, основной submit/action и safe-area. На самой странице feedback action MAY быть скрыт во избежание self-link.

### A5. Совместимость

Текущий пункт SHALL оставаться единственным `aria-current="page"`, включая внутренние ОТиЗ routes. Прямые route permissions, logout, session, append-only facts и существующая OTIZ internal navigation MUST NOT измениться. Календарь вынесен в GitHub issue #203 и не входит в этот срез.
