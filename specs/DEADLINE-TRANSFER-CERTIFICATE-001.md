# DEADLINE-TRANSFER-CERTIFICATE-001

## Простыми словами

ФКР прикладывает PDF-справку, дату документа и новый срок. Документ и срок сохраняются атомарно. Исправление создаёт новую версию; ОТиЗ видит основание следующего расчёта. Срез входит в №66, подключение к расчёту и выплатам проверяется отдельно.

## Public seam

`FMonitor2\DeadlineTransferCertificate\DeadlineTransferCertificates(mysqli $db,string $prefix,Closure $clock)`. `submit(array $command,Closure $readChunk): array`; callback returns a nonempty string of at most65536 bytes or null for EOF. Empty/oversized callback chunk or exception is STORAGE_UNAVAILABLE; more than20MiB, empty/invalid/unsafe PDF is INVALID_PDF. Clock returns exact recorded-at ISO timestamp. No caller-owned transaction is allowed.

Command requires requestId canonical lowercase UUIDv4, installationCaseId positive integer, actorId positive integer, expectedVersion integer>=0, certificateDate/newDeadline exact ISO calendar dates, correctionReason null|string, sourceLabel/sourceLocator nonempty trimmed strings<=500characters, mediaType exactly application/pdf. Initial expectedVersion0 requires null reason; correction expectedVersion>0 requires nonempty reason<=1000characters. No relation between certificate date, deadline, today or report date is imposed.

Success returns `{status:'accepted'|'replayed',revision:revision}`. DomainException reasons: FORBIDDEN, INVALID_COMMAND, INVALID_PDF, CASE_NOT_FOUND, OPERATION_CONFLICT, STALE_REVISION, STORAGE_UNAVAILABLE, OUTCOME_UNKNOWN. Failed precommit operations create no revision/receipt/blob. Unknown commit never claims rejection/success; same-identity replay resolves it. Authorization precedes callback and case lookup.

Revision exact metadata: id,installationCaseId,revisionNumber,previousRevisionId|null,certificateDate,newDeadline,correctionReason|null,actorId,recordedAt,sourceLabel,sourceLocator,pdfSha256,byteSize. IDs/version/size are integers. Read never contains PDF bytes or filesystem paths.

`read(int $actorId,int $caseId): array` returns `{current:null|revision,history:list<revision>}` ordered version ascending. `download(int $actorId,int $revisionId): array` returns `{mediaType:'application/pdf',filename:string,bytes:string,byteSize:int,pdfSha256:string}` with safe filename. Missing case/revision throws CASE_NOT_FOUND. Read and download enforce authorization before data disclosure.

`currentEvidence(int $caseId): ?array` is the read seam consumed internally by the already-authorized publication owner; it is not an HTTP endpoint. No certificate returns null. A valid result contains revision metadata plus source envelope (label, locator=`fm2_deadline_certificate_revisions/<id>`, contentSha256=SHA256 of canonical ordered revision metadata JSON, unescaped Unicode/slashes). Damaged hash/size/dates/linear lineage throws CERTIFICATE_EVIDENCE_INVALID and cannot silently fall back to the plan. Current evidence has no document-date cutoff.

## Authorization and persistence

Exact local capabilities: deadline_certificate.write defaults to active fkr_operator/manager; deadline_certificate.read defaults to those roles and otiz_specialist. Disabled users/roles, uppercase permission, otiz.manage or access.administer alone confer no access. Existing role IDs receive these additional grants during v26 migration; later fresh provisioning receives them through MariaDbInitialOwnerProvisioning::provision and LocalRoleCatalog. This names the actual current permission owner; a new role-import feature is not introduced. Existing grants are preserved.

Canonical v26 extends v25 with certificate roots, immutable revisions, idempotency operations and PDF chunks. PDF bytes are bounded BLOB chunks in immutable rows linked to the revision; the same DB transaction saves metadata/hash/bytes and advances the root pointer. This replaces the unapproved old filesystem staging design, eliminating orphan/finalize states. Existing mariadb-dump --hex-blob backup preserves exact bytes. Current recovery inventory includes all new tables/counters; old profiles stay unchanged. Actual DDL must have uniqueness for case root, root+version and actor+requestId, and foreign keys for previous revision links. Bounds and valid linear history are enforced by the application; no SQL CHECK constraints are required. Revision rows cannot be overwritten by the application.

Serialize initial/correction by locking the installation-case row. Concurrent initial attempts yield one accepted initial; same expectedVersion corrections yield at most one new revision. Fingerprint includes the declared command fields in their fixed contract order and the PDF hash; associative-key insertion order and undeclared transport-only fields do not change identity (extra fields are ignored). Same actor/requestId/fingerprint returns the original revision even after corrections; changed content or metadata gives OPERATION_CONFLICT. Stale expectedVersion gives STALE_REVISION. Retry cannot duplicate facts. DB commit failure leaves no activated partial certificate; ambiguous connection loss returns OUTCOME_UNKNOWN.

## Acceptance

Schema v26: roots columns installation_case_id BIGINT UNSIGNED primary key, current_revision_id nullable BIGINT UNSIGNED, current_version INT UNSIGNED. Revisions columns id BIGINT UNSIGNED auto_increment primary key, installation_case_id BIGINT UNSIGNED, revision_number INT UNSIGNED, previous_revision_id nullable BIGINT UNSIGNED, certificate_date DATE, new_deadline DATE, correction_reason nullable VARCHAR(1000), actor_id BIGINT UNSIGNED, recorded_at VARCHAR(40), source_label VARCHAR(500), source_locator VARCHAR(500), pdf_sha256 CHAR(64), byte_size INT UNSIGNED. Unique installation_case_id+revision_number; FK installation_case_id to installation cases, previous_revision_id to revisions. Operations actor_id BIGINT UNSIGNED + request_id CHAR(36) composite primary key, request_sha256 CHAR(64), revision_id BIGINT UNSIGNED FK to revisions. All unspecified columns NOT NULL. Exact schema fingerprint must reject incompatible existing tables before applying new DDL. PDF chunks table `fm2_deadline_certificate_pdf_chunks`: revision_id BIGINT UNSIGNED FK, chunk_no SMALLINT UNSIGNED, bytes MEDIUMBLOB; composite primary key(revision_id,chunk_no), contiguous chunks from0, each1..65536bytes, at most320chunks, concatenated total<=20MiB. Write/read each chunk in bounded SQL statements so the20MiB upload limit works with the existing16MiB packet limit without changing shared server configuration. New current recovery inventory has77tables and42auto-increment owners; the four new tables and only revisions auto-increment extend upstream feedback v25. No additional payment-lifecycle migration belongs to this issue.

Optional constructor observer `?Closure $observe=null` is a verification seam notified with phase `beforeCommit`/`afterCommit`, absent in production composition. Exception beforeCommit maps STORAGE_UNAVAILABLE with rollback; exception afterCommit maps OUTCOME_UNKNOWN, retaining committed revision/receipt for safe replay. It never bypasses authorization or chooses business outcomes.

## Yii adapter

GET /pilot/objects/<object>/deadline-certificates displays form/history; POST the same route submits PDF, certificateDate, newDeadline, requestId, expectedVersion, correctionReason and _csrf (actor comes only from session, case resolved from object). Source metadata is derived from the accepted upload by Yii: sourceLabel «Справка о переносе срока», sourceLocator `yii-upload/<requestId>`; no source metadata input fields are shown to the user. GET /pilot/objects/<object>/deadline-certificates/<revision>/pdf downloads only a revision belonging to that object. CSRF required; wrong methods405, missing object/revision404, forbidden403, invalid422, conflict409, unavailable503. Success303 returns to object certificate history. Card links to history for readers; form only for writers. Show current deadline, document date, all revisions, actor/time/reason and PDF links. Use existing shlz layout with mobile width; no bytes in HTML/JSON/logs. PDF response application/pdf, attachment safe filename, private,no-store and nosniff. Dates and recorded-at timestamp appear in their stored ISO form; actor ID is visible with the name. The Yii adapter constructs the service through Yii::createObject(Certificates::class, [$db,$prefix,$clock]); the ordinary DI container permits a test-only observer substitution without a production fault flag. STORAGE_UNAVAILABLE and OUTCOME_UNKNOWN both map to503; unknown outcome must preserve the request identity for retry.

## Boundaries

Application owns facts; HTTP calls it. PDF parser mechanics may be adapted from the mature passive inspector; AssignmentOrderOriginal service/state is not the certificate owner. Schema/readiness/default capabilities/backup and focused authorization/CSRF/history flows are required before completion. No production deployment/import/backfill. Calculator/publication/payment integration remains in the parent №66 contract.
