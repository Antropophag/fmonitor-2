# ORDER-PREPARE-004 — допустимость инженера строительного контроля

- Статус: `APPROVED`
- Версия: `0.1`
- Дата: `2026-08-27`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

## 1. Цель

Не допустить подготовку распоряжения с пользователем, который не является активным инженером строительного контроля.

Инженер допустим только при одновременном выполнении двух условий:

1. `active = true`;
2. `role = construction_control_engineer`.

Переданный идентификатор обязателен по `ORDER-PREPARE-001`; legacy-поле `responsstroicontrol` является только UI-подсказкой и не заменяет явный выбор.

## 2. Предусловия

- авторизация, обязательный состав и обязательные реквизиты объекта монтажа прошли;
- все выбранные монтажники прошли кадровую проверку `ORDER-PREPARE-003`;
- объект монтажа существует, доступен и находится в `needs_assignment_order` без версии и открытия;
- каталог пользователей доступен;
- renderer при отказе не вызывается;
- конкурентного изменения нет.

## 3. Поиск и правило

Каталог ищет пользователя по `controlEngineerUserId`. Отсутствующий пользователь, `active != true` или любая роль, отличная от точного значения `construction_control_engineer`, являются одним предметным отказом. Команда не раскрывает, какое именно техническое условие не прошло.

## 4. Наблюдаемый отказ

```text
accepted = false
violations = [
  {
    code: CONTROL_ENGINEER_NOT_ELIGIBLE,
    message: "Выбранный пользователь не является активным инженером строительного контроля.",
    field: controlEngineerUserId
  }
]
```

## 5. Порядок

```text
authorization
→ mandatory composition
→ required installation object data
→ all installer eligibility
→ control engineer lookup and eligibility
→ renderer and persistence
```

При кадровом отказе монтажников каталог инженеров не вызывается. При отказе инженера renderer не вызывается.

## 6. Состояние и аудит

Версии, назначения и артефакты не создаются; состояние, задача подготовки и шлюзы работ/чек-листа не меняются. Добавляется одно событие `assignment_order_prepare_rejected`:

```text
reasonCodes = [CONTROL_ENGINEER_NOT_ELIGIBLE]
installerCount = 1
controlEngineerProvided = true
controlEngineerEligible = false
```

Событие содержит также `installationObjectId`, `actorId`, серверный `occurredAt`. Оно не сохраняет идентификатор, ФИО, роль или статус активности выбранного пользователя и не сохраняет кадровые данные монтажников.

## 7. Исполняемые примеры

Во всех примерах объект монтажа `4512`, актор `18`, монтажник `1042`, инженер `73`, серверный момент `2026-08-27T14:00:00+03:00`; объект монтажа и монтажник полностью допустимы.

### A — неактивный инженер правильной роли

```text
userId = 73
active = false
role = construction_control_engineer
```

### B — активный пользователь неправильной роли

```text
userId = 73
active = true
role = fkr
```

### C — пользователь отсутствует в каталоге

```text
userId = 73
userSnapshot = null
```

Каждый отдельный вызов возвращает точный отказ раздела 4, оставляет исходное состояние без частичных изменений и добавляет ровно одно событие раздела 6. Fixture запрещает renderer.

Успешный пример `ORDER-PREPARE-002` уже доказывает положительную комбинацию `active = true` и `role = construction_control_engineer`.

## 8. Не входит

- управление пользователями и ролями;
- временные периоды действия роли;
- множественные роли одного пользователя — внутренний adapter обязан дать канонический признак требуемой роли;
- смена инженера и изменяющее распоряжение;
- ошибки/недоступность каталога;
- существующая версия, конкурентность, renderer/persistence failures;
- UI и HTTP.

## 9. Решения и доказательства

- `PRODUCT.md`: инженер выбирается из пользователей FMonitor; требуется активный пользователь соответствующей роли.
- [`fmonitor-2-primary-spec.md`](../docs/fmonitor-2-primary-spec.md): `CONTROL_ENGINEER_NOT_ELIGIBLE` и серверная проверка полномочий/инвариантов.
- [`ORDER-PREPARE-001.md`](ORDER-PREPARE-001.md): обязательный скалярный выбор инженера.
- [`ORDER-PREPARE-003.md`](ORDER-PREPARE-003.md): кадровая проверка всех монтажников имеет более ранний приоритет.
