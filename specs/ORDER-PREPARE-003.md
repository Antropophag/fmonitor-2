# ORDER-PREPARE-003 — кадровая допустимость выбранных монтажников

- Статус: `APPROVED`
- Версия: `0.2`
- Дата: `2026-08-27`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

## 1. Цель

Проверить за один вызов кадровую допустимость всех выбранных монтажников по фактам, известным на момент подготовки распоряжения, и вернуть полный список недопустимых участников без частичного результата.

Команда не предсказывает будущие кадровые события. Она использует актуальный кадровый снимок и уже известные границы трудовых отношений.

## 2. Предусловия

- авторизация, обязательный состав и полный набор обязательных реквизитов объекта монтажа прошли;
- объект монтажа существует, доступен и находится в `needs_assignment_order` без подготовленной/зарегистрированной версии и открытия;
- LegacyInstallationObject adapter предоставил актуальные плановые даты начала и завершения;
- кадровый каталог доступен;
- выбранный инженер допустим как принятое предусловие; его каталог не вызывается до успешной кадровой проверки всех монтажников;
- renderer не вызывается при кадровом отказе;
- конкурентного изменения нет.

`needs_assignment_order` с Актом ПТО не рассматривается как нормальное состояние этой команды: такое legacy-противоречие отбирается отдельным контрактом импорта/качества данных.

## 3. Бизнес-дата и известные факты

Дата распоряжения определяется из серверного момента команды в `Europe/Moscow` до кадровой проверки.

Монтажник кадрово допустим, только если одновременно:

1. найден в актуальном интеграционном каталоге по переданному табельному идентификатору;
2. `status = employed`;
3. `employedFrom` заполнена и не позже даты распоряжения;
4. `employedTo` отсутствует либо не раньше даты распоряжения;
5. если `employedTo` уже известна, она не раньше актуальной плановой даты завершения работ.

Условие 5 не предсказывает будущее: оно использует уже известную дату прекращения трудовых отношений. Равенство `employedTo` дате распоряжения или планового завершения допустимо: обе даты включительны.

## 4. Полный набор нарушений

После нормализации и удаления дублей команда проверяет всех монтажников в порядке первого появления во входе.

Для отсутствующего в каталоге монтажника:

```text
code: INSTALLER_NOT_IN_CATALOG
message: "Монтажник с табельным номером {tabId} отсутствует в актуальном кадровом каталоге."
field: installerTabIds[{index}]
```

Для найденного, но не покрывающего требуемые даты монтажника:

```text
code: INSTALLER_NOT_EMPLOYED
message: "Монтажник с табельным номером {tabId} не имеет подтверждённого периода трудоустройства на требуемый срок работ."
field: installerTabIds[{index}]
```

Один монтажник порождает не более одной violation. Отсутствие в каталоге имеет приоритет над проверкой содержимого кадрового снимка. Команда возвращает violations для всех недопустимых монтажников за один вызов.

## 5. Порядок проверки

```text
authorization
→ mandatory composition
→ required installation object data
→ Moscow assignment order date
→ all selected installer snapshots
→ control engineer
→ renderer and persistence
```

При любой кадровой violation каталог инженеров и renderer не вызываются.

## 6. Состояние и аудит отказа

При кадровом отказе версия, назначения и артефакты не создаются; `processState`, задача подготовки и шлюзы работ/чек-листа не меняются. Добавляется одно событие `assignment_order_prepare_rejected`:

| Поле | Значение |
|---|---|
| `reasonCodes` | уникальные коды в порядке первого появления в violations |
| `installerCount` | количество нормализованных уникальных непустых идентификаторов |
| `invalidInstallerCount` | количество недопустимых монтажников |
| `controlEngineerProvided` | `true` |

Событие содержит также `installationObjectId`, `actorId`, серверный `occurredAt`. Оно не сохраняет табельные номера, ФИО, кадровые даты, идентификатор инженера или снимки объекта монтажа.

## 7. Исполняемый пример A — несколько кадровых причин

Серверный момент `2026-08-27T10:30:00+00:00` даёт дату распоряжения `2026-08-27` в `Europe/Moscow`. Плановое завершение — `2026-12-20`.

Команда:

```text
installationObjectId = 4512
installerTabIds = [9999, 1042, 2088, 3001, 3002, 3003, 4001]
controlEngineerUserId = 73
actorId = 18
```

Кадровые факты:

```text
9999: отсутствует в каталоге

1042:
  status = dismissed
  employedFrom = 2024-02-01
  employedTo = 2026-08-20

2088:
  status = employed
  employedFrom = 2025-05-10
  employedTo = 2026-11-30

3001:
  status = employed
  employedFrom = null
  employedTo = null

3002:
  status = employed
  employedFrom = 2026-09-01
  employedTo = null

3003:
  status = employed
  employedFrom = 2024-01-01
  employedTo = 2026-08-20

4001:
  status = employed
  employedFrom = 2026-08-27
  employedTo = 2026-12-20
```

Монтажник `2088` трудоустроен на дату распоряжения, но уже известная дата увольнения раньше планового завершения, поэтому он также недопустим. `3001` не имеет доказанной даты начала трудовых отношений, `3002` начинает их позже даты распоряжения, а у `3003` уже закончился период при формальном `status = employed`. `4001` допустим: равенство `employedFrom` дате распоряжения и `employedTo` плановому завершению подтверждает включительность обеих границ и не создаёт violation.

Ожидается:

```text
accepted = false
violations = [
  { code: INSTALLER_NOT_IN_CATALOG,
    message: "Монтажник с табельным номером 9999 отсутствует в актуальном кадровом каталоге.",
    field: installerTabIds[0] },
  { code: INSTALLER_NOT_EMPLOYED,
    message: "Монтажник с табельным номером 1042 не имеет подтверждённого периода трудоустройства на требуемый срок работ.",
    field: installerTabIds[1] },
  { code: INSTALLER_NOT_EMPLOYED,
    message: "Монтажник с табельным номером 2088 не имеет подтверждённого периода трудоустройства на требуемый срок работ.",
    field: installerTabIds[2] },
  { code: INSTALLER_NOT_EMPLOYED,
    message: "Монтажник с табельным номером 3001 не имеет подтверждённого периода трудоустройства на требуемый срок работ.",
    field: installerTabIds[3] },
  { code: INSTALLER_NOT_EMPLOYED,
    message: "Монтажник с табельным номером 3002 не имеет подтверждённого периода трудоустройства на требуемый срок работ.",
    field: installerTabIds[4] },
  { code: INSTALLER_NOT_EMPLOYED,
    message: "Монтажник с табельным номером 3003 не имеет подтверждённого периода трудоустройства на требуемый срок работ.",
    field: installerTabIds[5] }
]
```

Аудит содержит:

```text
reasonCodes = [INSTALLER_NOT_IN_CATALOG, INSTALLER_NOT_EMPLOYED]
installerCount = 7
invalidInstallerCount = 6
controlEngineerProvided = true
```

Исходное состояние сохраняется; каталог инженеров и renderer запрещены fixture и не вызываются.

## 8. Не входит

- порог свежести кадрового каталога и поведение при недоступности интеграции;
- конфликты загрузки и параллельные назначения;
- должностная квалификация помимо присутствия в каталоге монтажников;
- неизвестные будущие увольнения;
- повторная кадровая проверка при открытии работ;
- допустимость инженера;
- успешная бригадная подготовка, UI и HTTP.

## 9. Решения и доказательства

- `PRODUCT.md`: монтажник выбирается только из актуального интеграционного каталога трудоустроенных.
- [`fmonitor-2-primary-spec.md`](../docs/fmonitor-2-primary-spec.md), `DECISION-006`: проверка на дату распоряжения, блокировка по уже известному увольнению до планового завершения и повторная проверка при открытии.
- `CONTEXT.md`: кадровый статус — датированный факт из кадровой системы, а не общий флаг «активен».
- [`ORDER-PREPARE-002.md`](ORDER-PREPARE-002.md): `Europe/Moscow`, снимок монтажника и успешный публичный seam.
