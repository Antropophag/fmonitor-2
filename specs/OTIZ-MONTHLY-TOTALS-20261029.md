# ОТИЗ: месячные итоги 29.10.2026

Показать в XLSX закрытую за календарный месяц сумму: фактически выплачено плюс
дисциплинарные удержания плюс удержания за сроки. Детализация по объекту/монтажнику
и отдельный итог по объекту. Резерв не является закрытием или штрафом.

Public read: `MariaDbOtizMonthlyTotals(Connection, prefix)->read(actor, 'YYYY-MM', objectIds)`.
Возвращает `rows` (objectId,employeeId,tabNumber,name,paidCents,disciplineCents,
deadlineCents,totalCents), `objects` (objectId и те же денежные итоги) и `month`.
Доступ только действующему otiz.manage; неизвестный actor, чужие роли, неверный месяц
или invalid object ID отклоняются. Чтение не меняет facts/receipts.

- Выплаты берутся из сохранённых recipient obligations с активным payment fact,
  по фактической payment_date в выбранном месяце. Отменённая отметка не учитывается.
  Факт оплаты относится к всему расчёту; не размножать его сумму при join по объектам.
- Удержания учитываются у действующего accepted расчёта в месяце report_date.
  Draft/cancelled/deleted не закрывают суммы. Сторнированная отметка оплаты сама по
  себе не снимает принятого удержания. Отдельный release резерва не повторяет штрафы.
- Общие удержания за сроки и дисциплину один раз распределяются по исходным
  положительным originalWeight (fallback weight), с существующим deterministic
  largest-remainder и stable employee identity. Личные удержания добавляются ровно
  своему получателю. Суммы не выводятся из текущего статуса/КТУ/кадрового каталога.
- Нет доказуемых весов/сохранённых исходных данных — явная неполнота (`incomplete`
  и описание), не фиктивный ноль и не произвольное равное деление.
- rows включают всех получателей месяца на указанных объектах, даже отсутствующих
  в открытом snapshot. objects равны сумме rows, без дубля объектных полей.
- Это актуальная сводка ledger за месяц на момент выгрузки, она явно подписана.
  Не выдавать её за неизменяемую часть старого расчёта. Основные сохранённые суммы
  исторического XLSX не менять. Добавить месячный итог в основной лист для совпавших
  object/employee и отдельные листы «Месяц по работникам»/«Месяц по объектам».

Независимый пример (копейки): gross1000000, Ксс9000, common discipline100000,
веса A60/B40, personal A10000 → payable A470000/B320000. При payment в том же
месяце deadline A60000/B40000, discipline A70000/B40000, closed A600000/B400000,
object1000000. После отмены ошибочной оплаты paid0, удержания210000 сохраняются.
Расчёт сентября, оплаченный в октябре, даёт выплаты октябрю, удержания сентябрю.
