# ОТИЗ: исключающие фильтры отчёта

Владелец подтвердил29.10: приставная шахта — материал «Металлокаркас и стекло»
(canonical raw123 / saved shaftBp12500). Отпуск пока учитывается ручным исключением
с причиной и резервом; не создавать выдуманный кадровый статус отпуска.

Фильтры внутри открытого расчёта: excludeFrame, excludeCompleted, excludeDismissed,
onlyReserved (boolean query0/1). Использовать сохранённые facts расчёта, не текущие
изменившиеся карточки. completed/completed Russian label — завершённый объект;
dismissed — кадровый статус сохранённого получателя; unknown не превращается в known.
Фильтры применяются до группировки/пагинации, одинаковы для двух группировок.

Public pure read: `OtizCalculationReportFilter::apply(calculation, filters)` returns
`calculation` (filtered copy), `filters`, `totalCents`, `reservedCents`,
`excludedRecipients`. Original argument unchanged. Сохранённые суммы отдельных
получателей никогда не пересчитываются/не распределяются между оставшимися.
Пустые объекты убираются; payable/reserved totals filtered copy равны сумме выбранных
recipients. Объектные исходные gross/fund/deadline остаются подписанными исходными
суммами; не выдавать их за выбранную сумму работников.

UI ясно разделяет «Весь расчёт» и итоги отбора. Отбор не изменяет состав утверждения
или выплаты; финансовые команды и подтверждения всегда про весь сохранённый расчёт.
Для реального исключения из выплаты используется решение ОТИЗ с причиной/резервом.

Добавить отдельную выгрузку `mode=report`: «Отчёт с отбором. Не основание выплаты».
Она содержит ровно отобранные objects/recipients и их суммы, резерв/основания,
перечень применённых фильтров; месячные строки тоже ограничены выбранными identities.
Обычный historical/payment export сохраняет весь расчёт и штатный admission;
параметры фильтра не должны превращать частичный отчёт в платёжный реестр.
Исторические snapshot, obligations, payments и reserve не меняются от GET/export.
