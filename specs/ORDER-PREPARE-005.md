# ORDER-PREPARE-005 — запрет повторной первой подготовки

- Статус: `APPROVED`
- Версия: `0.1`
- Дата: `2026-08-27`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

> Срез использует утверждённый в `TERMINOLOGY-OBJECT-001` шов объекта монтажа и готов к Gate 1.

## 1. Цель

Не допустить, чтобы повторный вызов первой подготовки заменил, пересобрал или дополнил уже существующую актуальную версию распоряжения.

Если актуальная версия имеет статус `prepared` либо `registered`, изменение состава начинается отдельной командой изменяющего распоряжения. `prepareAssignmentOrder` не является edit/retry-командой.

## 2. Предусловия

- актор имеет полномочие `assignment_order.prepare`;
- обязательный состав передан;
- по объекту монтажа уже существует актуальная версия `1` в статусе `prepared` либо `registered`;
- версия содержит неизменяемые снимки, назначения и артефакты;
- остальные сведения новой команды могут отличаться, но не должны загружаться или проверяться;
- каталоги объекта/людей и renderer при отказе не вызываются.

## 3. Порядок

```text
authorization
→ mandatory composition
→ current process/version check
→ installation object data and people catalogs
→ renderer and persistence
```

Авторизация и обязательный состав сохраняют ранее утверждённый приоритет. После их прохождения наличие актуальной версии проверяется раньше обязательных реквизитов объекта и людей, чтобы повторная команда не раскрывала и не вычисляла нерелевантные ошибки.

## 4. Наблюдаемый отказ

Для обоих статусов возвращается единый ответ:

```text
accepted = false
violations = [
  {
    code: ASSIGNMENT_ORDER_ALREADY_PREPARED,
    message: "По объекту монтажа уже существует актуальное распоряжение. Для изменения состава подготовьте изменяющее распоряжение.",
    field: null
  }
]
```

Ответ не раскрывает статус и реквизиты версии сверх того, что распоряжение существует.

## 5. Неизменность и аудит

Существующая версия, снимки, назначения, артефакты, регистрационный номер, события, состояние дела, задачи и шлюзы работ/чек-листа остаются побайтно неизменными. Renderer и legacy-проекция не вызываются.

Добавляется только одно событие `assignment_order_prepare_rejected`:

```text
reasonCodes = [ASSIGNMENT_ORDER_ALREADY_PREPARED]
installerCount = <число нормализованных уникальных входных монтажников>
controlEngineerProvided = true
currentOrderVersion = 1
```

Аудит не сохраняет статус или регистрационный номер текущей версии, входные табельные номера, выбранного инженера, ФИО либо новые снимки команды.

## 6. Исполняемые примеры

Оба примера вызывают `prepareAssignmentOrder(4512, [2088], 74, 18)` при существующей неизменяемой версии `1`. Новые идентификаторы намеренно отличаются от сохранённого состава.

### A — версия `prepared`

```text
processState = assignment_order_prepared
version = 1
status = prepared
registrationNumber = null
```

### B — версия `registered`

```text
processState = ready_to_open
version = 1
status = registered
registrationNumber = 12-Р
```

Каждый отдельный вызов возвращает точный отказ раздела 4. Вся исходная проекция, включая текущую версию и прежние события, сохраняется; в конец `events` добавляется только событие отказа раздела 5. Fixture запрещает чтение installation object snapshot, каталогов людей и renderer.

## 7. Не входит

- изменяющее распоряжение и его effective date;
- повтор команды после неизвестного результата/idempotency key;
- конкурентные вызовы, lock version и `CONCURRENT_MODIFICATION`;
- исправление регистрационного номера;
- отмена подготовленной версии;
- UI и HTTP.

## 8. Решения и доказательства

- `PRODUCT.md` и `CONTEXT.md`: подготовленная версия неизменяема; изменение состава создаёт новое распоряжение.
- [`fmonitor-2-primary-spec.md`](../docs/fmonitor-2-primary-spec.md): `ASSIGNMENT_ORDER_ALREADY_PREPARED` и append-only история.
- Решение владельца продукта `2026-08-27`: замена монтажников на объекте требует нового изменяющего распоряжения.
- [`ORDER-PREPARE-001.md`](ORDER-PREPARE-001.md): приоритет авторизации и обязательного состава.
