# OTIZ-SETTLEMENT-V2-001 — Расчёты, обязательства и выплаты ОТиЗ

Этот файл и delta specs change `redesign-otiz-settlements-v2` являются самодостаточным нормативным контрактом. Числовые ожидания M01–M24 задаются literal integer cents и не вычисляются тестируемым кодом.

Порядок источников: этот контракт и handoff v2; issue #257 для composition mismatch; PRODUCT/CONTEXT и pilot contracts; канонические normative inputs. HTML v3 определяет компоновку и действия, но не суммы, состояние, CSS, localStorage или demo debt.

Особые fail-closed условия: UNKNOWN norm/identity/admission остаётся UNKNOWN; draft финансово нейтрален; acceptance создаёт claim один раз; payment закрывает сохранённое обязательство и не списывает work/fund повторно; #257 запрещает acceptance/current-payment-export/payment всего объекта и требует replacement после resolution; historical read остаётся доступен.

## Public commands and state

Единственный public application owner предоставляет команды create/refresh/delete draft, save/remove deduction, save former-employee decision, accept, cancel, replace, mark paid и reverse payment. Каждая команда повторно проверяет `otiz.manage`, membership, operation UUID/payload fingerprint и expected revision; одинаковый replay возвращает сохранённый результат, другой payload с тем же UUID возвращает `OPERATION_CONFLICT`. Ошибка не оставляет частичных facts.

`draft` финансово нейтрален. `accepted` создаёт immutable entitlement claims и recipient obligations. `cancelled` сохраняет снимок и причину; accepted с payment/dependencies не отменяется простым маршрутом. Replacement атомарно отменяет только допустимое неоплаченное основание и принимает новый revision. Payment создаёт один package fact с явно введённой небудущей фактической датой; reversal с причиной деактивирует его, но не claims/accepted amounts. Нулевой obligation без payment fact не получает статус «выплачено».
