# ORDER-PREPARE-002-B — отказ при отсутствии адреса объекта

- Статус: `APPROVED`
- Версия: `0.1`
- Дата: `2026-08-27`
- Актор: сотрудник ФКР с полномочием `assignment_order.prepare`
- Публичный командный шов: `InstallationProcess.prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)`
- Публичный шов наблюдения: результат команды и `InstallationProcess.getInstallationObjectProcess(installationObjectId)`

## 1. Цель среза

Не допустить подготовки распоряжения, если в снимке legacy-объекта монтажа отсутствует отображаемый адрес объекта, обязательный для основного текста и приложения нормативного шаблона.

Срез проверяет только поле `address`, источником которого в пилоте является `fm_maintable.ordadr_address`. Остальные обязательные реквизиты объекта монтажа проверяются отдельными вертикальными срезами.

## 2. Предусловия

- актор имеет полномочие `assignment_order.prepare`;
- объект монтажа существует, доступен актору и входит в контур пилота;
- монтажное дело имеет состояние `needs_assignment_order`, ещё не открыто и не завершено;
- подготовленных или зарегистрированных версий распоряжения нет;
- дата Акта ПТО отсутствует;
- выбраны один допустимый монтажник и один допустимый инженер строительного контроля;
- регистрационный номер объекта, подъезд/секция и актуальные плановые даты начала и завершения заполнены;
- каталоги людей доступны, но при отсутствии адреса команда не должна обращаться к ним;
- renderer доступен, но при отсутствии адреса не должен вызываться;
- конкурентного изменения нет.

Авторизация и обязательность выбранного состава проверяются раньше реквизитов объекта монтажа согласно `ORDER-PREPARE-001`.

## 3. Вход и нормализация

Команда использует прежнюю сигнатуру без добавления поля адреса:

```text
prepareAssignmentOrder(installationObjectId, installerTabIds[], controlEngineerUserId, actorId)
```

Адрес загружается через внутренний LegacyInstallationObject adapter как `installationObjectSnapshot.address`.

Адрес считается отсутствующим, если значение:

- равно `null`;
- является пустой строкой;
- после удаления пробелов по краям является пустой строкой.

Непустой адрес в этом срезе не нормализуется и не исправляется командой: подготовленная версия сохраняет снимок, предоставленный адаптером.

## 4. Действие и порядок проверок

После успешной авторизации и проверки обязательного состава команда загружает снимок объекта монтажа и проверяет адрес до:

1. обращения к кадровому каталогу;
2. обращения к каталогу инженеров;
3. определения бизнес-даты и создания версии;
4. вызова renderer;
5. изменения задач, назначений или legacy-проекции.

## 5. Наблюдаемый отказ

Если адрес отсутствует, команда возвращает:

```text
accepted = false
violations = [
  {
    code: INSTALLATION_OBJECT_REQUIRED_DATA_MISSING,
    message: "В объекте монтажа не заполнен адрес объекта.",
    field: address
  }
]
```

Одна отсутствующая причина порождает одну violation. Полный набор нескольких пропусков и нормативный порядок определяет `ORDER-PREPARE-002-E` после его утверждения.

## 6. Отсутствие частичного результата

После отказа:

- `processState` остаётся `needs_assignment_order`;
- версия распоряжения и назначения не создаются;
- документы и приложение не формируются;
- задача `prepare_assignment_order` остаётся открытой;
- работы и чек-лист остаются закрытыми;
- legacy-проекция не меняется;
- добавляется только один append-only факт отказа.

## 7. Аудит отказа

Система добавляет одно событие `assignment_order_prepare_rejected`:

| Поле | Значение |
|---|---|
| `installation_object_id` | запрошенный объект монтажа |
| `actor_id` | аутентифицированный актор |
| `occurred_at` | серверный момент решения |
| `reason_codes` | `[INSTALLATION_OBJECT_REQUIRED_DATA_MISSING]` |
| `missing_fields` | `[address]` |
| `installer_count` | количество нормализованных уникальных монтажников |
| `control_engineer_provided` | `true` |

Значения остальных реквизитов объекта монтажа, ФИО, табельные номера и идентификатор инженера в событии отказа не сохраняются.

## 8. Исполняемый пример A — пробельный адрес

Исходное состояние:

```text
installationObjectId = 4512
processState = needs_assignment_order
assignmentOrders = []
assignments = []
openTasks = [{ type: prepare_assignment_order, assigneeRole: fkr }]
installationOpened = false
checklistAvailable = false
events = []
```

Серверный момент:

```text
2026-08-27T11:45:00+03:00
```

Команда:

```text
installationObjectId = 4512
installerTabIds = [1042]
controlEngineerUserId = 73
actorId = 18
```

Снимок объекта монтажа:

```text
address = "   "
entrance = "2"
objectRegistrationNumber = "77-000123"
plannedStartDate = 2026-10-05
plannedFinishDate = 2026-12-20
ptoActDate = null
```

Ожидаемый результат команды — точный отказ из раздела 5.

`getInstallationObjectProcess(4512)` возвращает исходное состояние с единственным добавленным событием:

```text
type = assignment_order_prepare_rejected
occurredAt = 2026-08-27T11:45:00+03:00
actorId = 18
payload.reasonCodes = [INSTALLATION_OBJECT_REQUIRED_DATA_MISSING]
payload.missingFields = [address]
payload.installerCount = 1
payload.controlEngineerProvided = true
```

Кадровый каталог, каталог инженеров и renderer не вызываются. Это проверяется поведением fixture: данные людей и артефакты в примере намеренно не задаются, поэтому преждевременный вызов сделает тест красным по неверной причине реализации.

## 9. Отказы и приоритет

- `FORBIDDEN` имеет приоритет и не раскрывает отсутствие адреса.
- `INSTALLER_REQUIRED` и `CONTROL_ENGINEER_REQUIRED` возвращаются до загрузки снимка объекта монтажа.
- Этот срез добавляет только `INSTALLATION_OBJECT_REQUIRED_DATA_MISSING` для `field = address`.

## 10. Не входит в срез

- отсутствие подъезда/секции, регистрационного номера и плановых дат;
- объединение нескольких отсутствующих полей;
- форматная или адресная верификация непустого значения;
- Акт ПТО, состояние объекта монтажа и существующая версия;
- допустимость монтажника и инженера;
- ошибки LegacyInstallationObject adapter;
- ошибки renderer/persistence и конкурентность;
- успешная подготовка;
- UI и HTTP.
