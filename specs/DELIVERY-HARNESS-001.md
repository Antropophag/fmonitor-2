# DELIVERY-HARNESS-001

## Простыми словами
Обычное поручение получает короткую актуальную сводку, подготовленный пакет существующего процесса и сохраняемые результаты проверок. Экономию общего количества токенов не выводим из размера логов.

## Actor, authorization and seam
Владелец поручает issue или продолжение; root определяет scope/spec/tests, отдельный executor реализует, независимый reviewer проверяет Gates3/5. Публичные seams: tools/delivery/harness.py, change-verification.py, существующий verification runner и поддерживаемые Codex hooks. Чтение о проекте не запускает delivery. Hooks не вызывают LLM и не выполняют продуктовые проверки сами. Никаких merge/deployment или записи WIP.

## R1 — Measurement and runner
`harness.py run [--reason TEXT] [--fixture PATH] [--intended-red MARKER] -- ARGV...` запускает argv последовательно, сохраняет запись JSON и полные stdout/stderr вне checkout. Для GREEN печатает только id, outcome и record_path. Остальные metadata, включая summary_bytes, остаются в retained JSON; отказ дополнительно возвращает exit_code, stdout_path, stderr_path, excerpt и output_bytes. Запись содержит argv/cwd, timestamps/duration, source identity, environment digest, fixture digest, reason. First run reason initial; repeat reasons identify source/environment/fixture change, correction, independent reproduction or instability. No GREEN reuse. Нет timeout/signal PASS.
Outcome: exit0 GREEN; nonzero REGRESSION_FAILURE; missing executable/SETUP_FAILURE marker SETUP_FAILURE; signal INTERRUPTED; unclassifiable UNKNOWN. Intended RED только nonzero regression с явным ожидаемым marker; setup/signal/UNKNOWN имеют приоритет. Фактический child exit сохраняется в записи; CLI возвращает fail-closed статус outcome согласно правилу ниже (signal => conventional 128+signal CLI). Shell pipeline вызывается явно с pipefail; перенаправление summary не меняет child exit. Диагностический запуск плана сохраняет все результаты выбранной фазы даже после отказа; default fail-fast допускается. Markers не теряются за truncation. Полные bytes хранятся без truncation, короткий excerpt не более 4KiB. Успешный 100KiB лог должен давать summary <10KiB на тех же bytes.
`report` формирует JSON программно из уникальных records/events, не удваивает повторное чтение. Счётчики checks, agent tasks/calls, review returns и output coverage имеют явные области охвата. Недоступные показатели UNKNOWN. Token totals/deltas различаются; cached input является частью input, reasoning частью output; не складывать subsets. Сессии/субагенты дедуплицируются по identity и watermark. Нет billing/weekly-limit estimates.

## R2 — State and integration
`state` определяет exact HEAD/worktree/dirty/source, PR state/head/merge и CI exact SHA посредством bounded GitHub read. MERGED => next_action не publish; при недоступности UNKNOWN и checked_at/last_success_at, прежнее значение не выдаётся за live. Deployment UNKNOWN без отдельного свидетельства. Read-only state не меняет tracked/untracked source. Owner intent остаётся в current-delivery-goal: очередь/ограничения/ссылки без mutable HEAD/PR/CI.
Поддерживаемые установленным Codex SessionStart/resume и task-start hooks предоставляют короткий контекст и маршрут с receipt вне repo. `doctor` отличает configured от observed и явно показывает отсутствующую интеграцию. Обычный read-only вопрос не запускает pipeline. Однократная локальная настройка сохраняет чужие настройки; no fake supported fields. Smoke реального клиента подтверждает доставку context на start/resume и обработку обычного задания, либо конкретный недоступный участок остаётся явно UNKNOWN и не заявляется выполненным.

## R3 — Prepared review
`prepare --input PATH --base REF --role root|executor|reviewer [--previous SNAPSHOT] [--findings PATH]` обновляет существующий verification plan при drift, проверяет комплектность и whitespace, captures через review-source, пишет пакет вне checkout. Пакет содержит точный reconstructible snapshot, plan и digest, spec/rules/source links, роль, краткую сводку evidence с совпадающим source, relevant findings. Reviewer package без контракта/тестов/плана/необходимого evidence отклоняется; подготовка root до RED допускает отсутствующий будущий тест и явно сообщает это. Никакого APPROVED по факту подготовки. Неизменный код доступен в restored worktree. Staged/unstaged/untracked и modes учитываются; whitespace rejection до snapshot, без форматирования всего проекта. Delta содержит изменения относительно проверенного snapshot и исходные findings; изменение source не наследует approval. Старое evidence обозначается stale и не считается GREEN текущего source.

## Concrete v1 interface clarifications
- `run --timeout SECONDS`: timeout is INTERRUPTED, saved exit code nonzero. Explicit UNKNOWN marker is UNKNOWN even when paired with an expected RED marker. Known failure markers anywhere in saved streams must be discoverable in excerpt. Auto reasons are `initial`, `source_changed`, `fixture_changed`, `environment_changed`, `same_source_diagnostic`; supplied reason retained.
- `change-verification run --diagnostic` emits JSON with `results` (every argv/outcome/exit code), aggregate nonzero on any non-GREEN. It uses the same runner, not a second inventory.
- v1 hooks have no supported token fields. Any injected `usage` or `tokenUsage` in hook input is ignored. Token telemetry status and all numeric token counters are UNKNOWN, with reason and source. No telemetry importer or made-up event is required. If a future supported interactive transport is exposed, cumulative-versus-delta handling needs its own executable contract before claiming coverage.
- Hook stdout for context-producing events is documented `hookSpecificOutput: {hookEventName, additionalContext}`. PostToolUse stores only byte count and identity. SubagentStart/Stop dedupe by session/turn/agent; tool IDs are scoped by session. Review return is a SubagentStop whose documented `last_assistant_message` contains a verdict CHANGES_REQUESTED; only verdict is stored. Unknown returned text is not an approval or return. `doctor` reports receipt provenance/observed events, not a security attestation. Direct synthetic hook tests do not substitute for actual client smoke.
- Repo `.codex/hooks.json` is the canonical hook definition; existing global settings are never written. Once project/hook definitions are trusted through native Codex `/hooks`, ordinary start/resume works. `doctor` reports config path and observed events. In a client missing support, report limitations; never silently claim automatic integration.
- `state` JSON includes `source`, `head`, `dirty`, `github.headRefOid`, `ci: {status, source}`. `statusCheckRollup` comes from the PR head; a different HEAD or dirty source => `ci.status=UNKNOWN`. An exact clean head whose nonempty required checks all completed successfully => SUCCESS; queued/pending/failure remain distinct. No checks => UNKNOWN. Old GitHub failure retains only last_success_at metadata as live and sets UNKNOWN. Merged PR head may differ from local merge HEAD; MERGED still prevents duplicate publication, but never asserts exact local CI from that fact.
- `prepare` returns `package_path`, `snapshot`, `plan`, `plan_sha256`, `role`, `approval=NOT_REVIEWED`, `missing_tests`, `contracts`, `rules`, `sources`, `evidence`, `previous`, `findings` and optional `delta`. Evidence list links current exact-source runner records; stale records excluded. `--evidence PATH` selects a retained record explicitly and rejects mismatch. Reviewer requires evidence and existing tests, executor/root links contract/plan and reports omissions. Source identity is independent of index staging layout so a restored snapshot has the same artifact bytes/modes. Package plan must be current at capture. `--previous` requires findings and records previous manifest identity; source changes never inherit an approval. Root can prepare planned future tests before RED, marked in missing_tests.

Reviewer evidence MUST match a mapped acceptance argv in the current plan (all mapped acceptance tests covered); unrelated same-source successful commands are rejected as irrelevant evidence. Executable runtime absolute path may be normalized to its resolved equivalent, never a different test.

`prepare --gate 3|5` defaults to 5. Gate3 reviewer accepts mapped INTENDED_RED evidence (or existing GREEN regressions) and Gate5 requires GREEN. All mapped acceptance commands must be covered; pending independent review remains NOT_REVIEWED. Evidence environment must match current substantial environment; tracked and untracked whitespace are both checked. Runner-parent SIGTERM/KeyboardInterrupt preserves partial logs and INTERRUPTED record. Explicit SETUP_FAILURE/UNKNOWN marker takes precedence over child exit0; actual child exit is retained even when aggregate outcome rejects GREEN.

## Supported native installation fallback
Observed 0.154.0 CLI / 0.153.1 managed runtime loads user hooks.json but not this worktree's project layer, even after project trust. `install [--config PATH]` defaults to native user hooks.json, atomically merges only the harness hook groups and preserves foreign settings/events; repeated installation is byte-idempotent and invalid JSON is rejected unchanged. It stores a small non-LLM dispatcher outside source which limits execution to registered Git common directories (including worktrees) and invokes the current checkout's harness. Other repositories receive no output or pipeline. Canonical repo hook definitions remain one representation, not duplicate project config. Actual startup/task/resume smoke must now exercise this fallback, with real receipts; configured alone remains insufficient.

## Outcome marker grammar — real CI correction
Only an explicit line beginning with SETUP_FAILURE or UNKNOWN (optional horizontal indentation), followed by `:` or end of line, is a control marker. Domain identifiers such as ASSIGNMENT_ORDER_UNKNOWN_EMPLOYMENT_SCHEMA_COLLATION_001_OK and SOURCE_DICTIONARY_VALUE_UNKNOWN, or those words inside descriptive text, are ordinary output. They cannot turn exit0 into failure/UNKNOWN. Explicit markers retain precedence over intended RED and exit0 and must be present in the excerpt even after earlier domain words and long noise. This corrects CI34496967157's two false classifications without changing product suites or suppressing genuine unknown/setup outcomes.
