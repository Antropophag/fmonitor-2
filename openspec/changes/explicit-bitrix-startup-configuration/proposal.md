## Why

Оператор не может запустить `make up` из отдельного клона: Make извлекает настройки из соседнего легаси через PHP на хосте. Срез #42 удаляет эту зависимость запуска после подготовки проверок и установки в #43/#44.

## What Changes

- Явные настройки вебхука и отделов в локальном `.env`, безопасные примеры и инструкция запуска средствами Git, Make и Docker Compose.
- Контейнерная подготовка приватной конфигурации через существующий механизм `WorkerConfiguration`; ошибки до запуска синхронизации без раскрытия значений.
- **BREAKING**: удаление `rapid-pilot/export-legacy-bitrix-secret.php` и извлекающей настройки зависимости Make; оператор переносит настройки в `.env` самостоятельно.
- По уточнению владельца штатный `make up` запускает пилот вместе с Bitrix; отдельная команда `up-bitrix` удаляется. Существующий Docker secret для worker сохраняется.

## Capabilities

### New Capabilities

- `deployment/explicit-bitrix-startup`: самостоятельная настройка и запуск Bitrix из `.env` без соседнего репозитория и PHP на хосте.

### Modified Capabilities

Нет.

## Impact

Актор: оператор развёртывания. Публичная точка: `make up`, включая отказ запуска при отсутствии настроек. Источник требований: [issue42](https://github.com/Antropophag/fmonitor-2/issues/42) и сообщение владельца с объёмом PR. Код служит свидетельством текущей связи, а не источником новых требований.

Затрагиваются Make, Compose, `.env.example`, исключения build context, контейнерный адаптер подготовки, документация и проверки запуска. Владелец синхронизации остаётся `MariaDbWorkforceSynchronization`, worker вызывает штатный CLI.

Не входят: переработка синхронизации и scheduler, production runtime (#33), схема ОТиЗ (#24), карта владельцев (#32), продуктовые изменения #38–40. Продуктовых UNKNOWN/NEEDS_GRILL в этом срезе не выявлено.

Реализация изолирована в ветке `codex/issue-42-bitrix-config` от актуального main `1dd62c2e`; Make/Compose/WorkerConfiguration сверены. Незакоммиченный архитектурный аудит не использован как основание.
