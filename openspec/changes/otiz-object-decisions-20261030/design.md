## Context

Историческая таблица решений идентифицировала только расчёт и работника. В одном расчёте работник может участвовать в нескольких объектах, поэтому глобальное исключение нарушает уточнённое владельцем правило.

## Decisions

- `fm2_otiz_payment_decisions.object_id` nullable: `NULL` навсегда означает историческую область всего расчёта; новое UI пишет только точную область.
- Проекция сначала читает глобальное решение работника, затем переопределяет его решением точной пары. Другие пары не меняются.
- Команды и preview проверяют точное участие, редакцию и полномочие; write использует существующий operation receipt и блокировку расчёта.
- Замена расчёта копирует nullable область без reinterpretation. Уже принятые projection и payment facts не пересчитываются при чтении.
- Миграция 38 до DDL проверяет все существующие одноимённые компоненты, добавляет только отсутствующие совместимые части и повторно подтверждает форму. Recovery получает отдельный V38 профиль; V37 неизменяем.
- UI хранит objectId+employeeId во всех opener/editor/preview/recovery ключах. Для работника на нескольких объектах требуется явный выбор объекта. Ошибка показывается внутри ровно соответствующего recovered form.
- XLSX показывает объект решения; `NULL` подписан как «Все объекты расчёта».

## Verification and release

Root владеет спецификацией и regressions; реализацию financial/UI выполнил `/root/otiz_count_executor`, recovery/readiness — `/root/otiz_excel_executor`. Обязателен независимый final review. Поставка отделена от backup/preflight/migration/deploy и не выполняется до review. Полный CI и обычные гейты отложены решением владельца; focused financial invariants сохраняются.
