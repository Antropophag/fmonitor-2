## Why

При переходе между Yii-разделами свёрнутый сайдбар сначала серверно выводится раскрытым и только после запуска JavaScript принимает сохранённое состояние. Пользователь видит рывок макета. Одновременно часть интерфейсных пиктограмм остаётся самодельной либо использует неточный заменитель, хотя `shlz-ui` уже содержит подходящие публичные экспорты.

## What Changes

- Сохранённое состояние сайдбара применяется до первой отрисовки и остаётся тем же при переходах между разделами; без JavaScript серверный shell остаётся пригодным к работе.
- Проводится ограниченный аудит пользовательских SVG в рабочем Yii/pilot-контуре и подходящие случаи переводятся на закреплённые публичные экспорты `shlz-ui`.
- Календарь получает собственную календарную иконку вместо иконки сетки объектов; одинаковые семантики используют один и тот же закреплённый источник.
- Добавляются детерминированные проверки отсутствия рывка и происхождения заменённых иконок.
- Не меняются права, маршруты, доменные факты, порядок навигации и поведение операций.

## Capabilities

### New Capabilities

- `ui/sidebar-state-and-icons`: стабильное начальное состояние сайдбара и использование доступных семантически подходящих иконок `shlz-ui` в ограниченном рабочем контуре.

## Impact

Затрагиваются общий Yii shell/navigation bootstrap, закреплённые SVG-активы и несколько существующих UI-композиций. Источник иконок — только публичный `@shlz/icons` export, воспроизводимо собранный из чистого `shlz-ui origin/main`; грязный соседний checkout и его внутренние файлы не являются входом. `rapid-pilot` меняется только там, где он остаётся активным адаптером той же пользовательской композиции.
