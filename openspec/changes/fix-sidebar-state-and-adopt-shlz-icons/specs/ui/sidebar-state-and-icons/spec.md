## Purpose

Рабочий shell должен сразу показывать сохранённую ширину навигации и использовать однозначные корпоративные пиктограммы без визуального рывка между разделами.

## ADDED Requirements

### Requirement: Сохранённое состояние сайдбара применяется до первого отображения
При полном переходе между разрешёнными Yii-разделами система SHALL применить последнее сохранённое пользователем состояние сайдбара до первого видимого кадра страницы. Начальная отрисовка MUST NOT показывать раскрытый сайдбар, если сохранено свёрнутое состояние.

#### Scenario: Переход со свёрнутым сайдбаром
- **WHEN** пользователь свернул сайдбар и переходит по ссылке в другой разрешённый раздел
- **THEN** новая страница с первого видимого кадра показывает свёрнутый сайдбар без промежуточного раскрытия и без анимации от раскрытого состояния

#### Scenario: Переход с раскрытым сайдбаром
- **WHEN** пользователь оставил сайдбар раскрытым и переходит в другой разрешённый раздел
- **THEN** новая страница с первого видимого кадра показывает раскрытый сайдбар

#### Scenario: Хранилище состояния недоступно
- **WHEN** браузер запрещает чтение локального хранилища или сохранённого значения нет
- **THEN** страница остаётся работоспособной и показывает раскрытый сайдбар как безопасное начальное состояние

#### Scenario: JavaScript недоступен
- **WHEN** скрипты страницы не выполняются
- **THEN** серверная навигация остаётся раскрытой, видимой и доступной по клавиатуре

### Requirement: Переключение сохраняет состояние и доступное имя
Действие переключения SHALL сохранять выбранное состояние для последующих полных переходов и MUST синхронно обновлять видимое название, доступное имя и направленную пиктограмму управления.

#### Scenario: Пользователь сворачивает меню
- **WHEN** пользователь активирует управление раскрытого сайдбара
- **THEN** сайдбар сворачивается, состояние `false` сохраняется, а управление называется «Развернуть меню» и показывает пиктограмму раскрытия

#### Scenario: Пользователь раскрывает меню
- **WHEN** пользователь активирует управление свёрнутого сайдбара
- **THEN** сайдбар раскрывается, состояние `true` сохраняется, а управление называется «Свернуть меню» и показывает пиктограмму сворачивания

### Requirement: Подходящие рабочие пиктограммы происходят из shlz-ui
В пределах аудируемого Yii/pilot рабочего контура система SHALL использовать закреплённый публичный экспорт `shlz-ui` для каждой пиктограммы, которой в доступном публичном каталоге соответствует однозначная семантика. Замена MUST сохранять доступное имя элемента и MUST NOT менять его действие.

#### Scenario: Календарь в основной навигации
- **WHEN** пользователю доступен раздел «Календарь»
- **THEN** ссылка использует отдельную календарную пиктограмму `shlz-ui`, а не пиктограмму объектов или самодельную геометрию

#### Scenario: Одинаковая семантика в разных композициях
- **WHEN** календарное действие отображается в основной навигации, кнопке планирования или признаке запланированной инспекции
- **THEN** каждая заменённая композиция получает календарную геометрию из одного закреплённого публичного семейства `shlz-ui` с размером, заданным композицией

#### Scenario: Публичного подходящего экспорта нет
- **WHEN** аудит не находит семантически однозначного публичного экспорта `shlz-ui`
- **THEN** существующая пиктограмма не подменяется приблизительным символом, а случай остаётся явно перечисленным в аудите

### Requirement: UI-срез не меняет доменное состояние
Применение состояния сайдбара и отрисовка пиктограмм MUST NOT создавать доменные или аудиторские факты, изменять полномочия, маршруты, порядок навигации либо результаты прикладных команд.

#### Scenario: Повторное чтение разделов
- **WHEN** один и тот же пользователь повторно открывает аудируемые разделы в любом состоянии сайдбара
- **THEN** состав разрешённых ссылок и прикладные факты остаются неизменными
