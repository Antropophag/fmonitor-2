## Why

Рабочая очередь стройконтроля сейчас включает дела, которые уже перешли к
документарному закрытию. Инженер на этом этапе не выполняет следующего действия,
поэтому строка остаётся ложной рабочей задачей и мешает отличать актуальные
инспекции от завершённой части маршрута.

## What Changes

- Исключить из `GET /pilot/construction-control` дела, для которых зафиксирован
  акт ПТО, то есть начался этап документарного закрытия.
- Сохранить в очереди открытые монтажные работы, ещё требующие участия
  стройконтроля, с действующими правилами допуска, закрепления, сортировки и
  пагинации.
- Проверить поведение через реальный Yii2 HTTP seam и доказать отсутствие записей
  в процессную историю при чтении.
- Не менять ОТиЗ, формулы, completion-команды, карточку объекта, очередь ФКР,
  маршруты `rapid-pilot`, рабочий стенд или deployment.

## Capabilities

### New Capabilities

- `runtime/construction-control-working-queue`: состав рабочей Yii2-очереди
  стройконтроля после начала документарного закрытия.

### Modified Capabilities

Нет.

## Impact

Actor — пользователь с `construction_control.read`. Source oracle — подтверждённое
замечание владельца в issue #39 и принятые append-only `pto_act` facts. Target
public seam — `GET /pilot/construction-control` в Yii2. Ожидаемые изменения
ограничены read model очереди и focused Yii2-тестом; состояние дел и история не
переписываются. Release value — в рабочем списке остаются только задачи, где ещё
требуется участие стройконтроля.
