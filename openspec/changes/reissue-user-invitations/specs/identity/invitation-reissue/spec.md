## Purpose

INVITATION-REISSUE-001 позволяет администратору продолжить приглашение пользователя после потери ссылки, сохраняя учётную запись и историю.

Простыми словами: вернуться в пользователей, нажать перевыпуск и передать новую ссылку. Старую использовать уже нельзя. Пароль активного пользователя этим действием не сбрасывается.

## ADDED Requirements

### Requirement: Перевыпуск неиспользованного приглашения

Система SHALL разрешать активному пользователю с access.administer перевыпуск для существующего пользователя со status=1 и activation_state=invited. Результат — новая одноразовая ссылка на 24 часа; прежние неиспользованные приглашения отзываются атомарно. История строк, автор и время нового выпуска сохраняются; исходные хеши и сроки не переписываются. Токен хранится только в виде хеша вне кратковременной выдачи ссылки. Пользователь, пароль и роли не меняются. Последовательные повторные команды выпускают новые ссылки; действительна только последняя. Параллельные команды сериализуются по пользователю. Неуспех записи откатывает весь перевыпуск.

#### Scenario: Потерянная ссылка

- **WHEN** администратор создал приглашение, ушёл с экрана и вернулся, затем перевыпустил приглашение
- **THEN** он получает новую ссылку для того же пользователя; старая отклоняется; новая позволяет однократную активацию с назначенными ранее ролями

#### Scenario: Истёкшая ссылка

- **WHEN** неактивированный пользователь имеет просроченное приглашение
- **THEN** администратор может перевыпустить его с новым сроком 24 часа

### Requirement: Проверка прав и допустимого состояния

Система MUST проверять active/access.administer в прикладной операции для HTTP и CLI. HTTP требует POST и действующий CSRF. Нет полномочия — отказ access_denied; отсутствующий, заблокированный или активированный адресат — not_invited. Отказы не создают и не отзывают приглашений. CLI требует явного actor user ID и использует ту же проверку. GET не меняет факты.

#### Scenario: Отказ

- **WHEN** действие вызывает неадминистратор либо адресат уже активирован или заблокирован
- **THEN** ссылка не выдаётся, пользователь, роли и история остаются прежними

### Requirement: Статус и действие в каталоге

Каталог SHALL различать активных, заблокированных и ожидающих активации пользователей; для последних показывать состояние приглашения и кнопку «Перевыпустить приглашение». Для истёкшей или отсутствующей действующей ссылки перевыпуск также доступен. После POST ссылка выдаётся через прежний безопасный механизм одноразового показа.

#### Scenario: Возврат в каталог

- **WHEN** администратор повторно открывает каталог после ухода со страницы с выданной ссылкой
- **THEN** ожидающий активации пользователь остаётся доступен для перевыпуска и не считается заблокированным
