## Purpose

Фиксировать фактическое начало монтажа по подписанному распоряжению и открывать работы без отдельного действия стройконтроля, сохраняя историю и безопасный повтор загрузки.

## ADDED Requirements

### Requirement: Signed appendix owns start date

Система SHALL сохранять подтверждённую дату начала из приложения отдельно от даты документа и текущего плана. Система MUST немедленно открыть работы после успешной загрузки, включая будущую дату. Нормативная матрица: ACTUAL-START-FROM-ORDER-001 A1–A9.

#### Scenario: Future signed start
- **WHEN** сегодня05.09, documentDate04.09, а подтверждённое начало20.09
- **THEN** объект сразу открыт, чек-лист доступен, фактическое начало20.09 и реальное время открытия05.09 сохраняются раздельно.

### Requirement: Safe upload and opening replay

Система SHALL проверять полномочия и связывать дату с точным подписанным оригиналом. Повтор MUST не создавать повторное открытие; несовпадающие данные с тем же requestId MUST отклоняться. Принятый оригинал при временной ошибке открытия сохраняется, а UI явно сообщает о незавершённой операции.

#### Scenario: Retry after original commit
- **WHEN** PDF принят, но opening не завершился, и пользователь повторяет тот же запрос
- **THEN** сохранённый оригинал переиспользуется и открытие создаётся один раз.

### Requirement: Preserve first opening

Следующее распоряжение SHALL менять состав без перезаписи начала дела. Correction MUST сохранять историю и не менять уже принятую дату этого распоряжения после открытия.

#### Scenario: Later assignment
- **WHEN** новое распоряжение после открытия содержит другую дату начала
- **THEN** новый состав применяется по установленным правилам, а начало дела и первоначальный opening event остаются прежними.
