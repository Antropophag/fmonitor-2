## Why

Сотруднику ФКР и руководителю сейчас негде безопасно исправить обычные реквизиты существующего объекта: legacy mirror и импортный technical snapshot остаются read-only, а карточка не имеет отдельной команды с историей. Issue #222 нужен сегодня, чтобы исправления локальных непроцессных данных выполнялись в FMonitor без подмены интеграционных, процессных, вычисляемых или исторических фактов.

## What Changes

- Добавляется один application owner и один canonical Yii POST для атомарного редактирования фиксированного allowlist реквизитов объекта с `requestId`, `expectedRevision`, проверкой capability и доступа к объекту.
- Ручные поправки хранятся отдельно от legacy mirror и импортного technical snapshot; одно сохранение создаёт одно append-only событие с полным field diff, автором и серверным временем.
- Карточка получает только компактную кнопку-иконку; существующая компоновка карточки не меняется. Одна модалка на публичных компонентах `shlz-ui` содержит две группы: «Идентификация и размещение» и «Классификация оборудования».
- Редактируются адрес, подъезд, регистрационный и заводской номера, этажность, грузоподъёмность, скорость, тип шахты, материал стен шахты, тип лифта и признак спаренности. Кшах не вводится: он вычисляется из эффективного материала стен шахты.
- Исходный план доступен обычной правке только до его фиксации реальным документным/процессным фактом; зафиксированный срок и срок по справке меняются только существующим процессом переноса.
- Интеграционные, кадровые, документные, процессные, вычисляемые и системные данные не становятся полями свободного ввода даже при пустом значении или недоступном источнике.
- Эффективные значения подключаются к существующим карточке, очередям/поиску, документам, ERP matching и новым расчётам; старые документы, snapshots, выплаты и факты не переписываются.
- История карточки показывает все old → new значения одного сохранения, автора и время и предоставляет доступ к записям старше текущего лимита восьми событий.
- Общий close control `shlz-modal` получает читаемую и доступную иконку с полноценной зоной нажатия; остальные части существующих экранов не перерабатываются.

## Capabilities

### New Capabilities

- `objects/object-details-editing`: публичная команда, хранение overrides и append-only diff, effective-value reads, RBAC, Yii-редактор и история карточки для разрешённых реквизитов существующего объекта.

### Modified Capabilities

- Нет.

## Impact

- Затрагиваются native object-detail storage/readers, legacy import repeatability, object card/queue projections, ERP matching, Bitrix document-link lookup, новые OTIZ operands, Yii routes/controller/view/assets, local RBAC registry и canonical migrations/backup inventory.
- Потребуются новая capability `objects.details.edit`, additive schema migration, согласование всех реальных consumers эффективных значений и table-driven unit/DB/HTTP/browser проверки.
- Source oracle: issue #222, `PRODUCT.md`, `CONTEXT.md`, текущие object-detail/import/card/OTIZ/ERP seams и утверждённый владельцем прототип на локальном стенде.
- Target public seam: один application command, вызываемый canonical `POST /pilot/objects/<id>/details` и наблюдаемый через reload карточки и её общую историю.
- Release value: PR-ready bounded vertical slice без merge/deploy, реального импорта, внешних запросов при Save или пересмотра формул.
- Не входят создание/удаление и массовое редактирование объектов, универсальные формы/EAV/event-sourcing, редакторы справочников/RBAC, двусторонняя синхронизация, изменение process rules и redesign карточки.
