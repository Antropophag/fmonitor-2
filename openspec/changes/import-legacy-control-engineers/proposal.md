## Why

Штатный legacy-импорт переносит объекты монтажа, но оставляет указанный в `fm_maintable.responsstroicontrol` legacy user ID без канонической локальной identity. Поэтому на чистом стенде инженер строительного контроля отсутствует в справочнике пользователей, а объект нельзя достоверно показать или использовать как назначенный этому инженеру.

## What Changes

- Расширить read-only legacy snapshot активными инженерами, на которых ссылаются импортируемые объекты, используя `users.id` как устойчивую legacy identity и сохраняя source provenance.
- Через один публичный import application seam идемпотентно создавать локального пользователя инженера в неактивном состоянии «ожидает приглашения», назначать ему роль инженера строительного контроля и capability, но не создавать пароль, активную сессию или отправленное приглашение.
- Дать администратору возможность позднее явно сгенерировать/перевыпустить и отправить приглашение такому пользователю существующим административным flow; до активации вход запрещён.
- Идемпотентно связывать импортированное монтажное дело с локальной identity инженера на основании `responsstroicontrol`, сохраняя legacy ID и снимок исходных реквизитов для аудита.
- Повторный импорт с тем же source identity не создаёт дубликатов и не переписывает ручную коррекцию или исторический факт; неоднозначность, конфликт identity либо ссылка на отсутствующего/непригодного legacy-пользователя завершаются явным fail-safe результатом, а не подбором по ФИО.
- Объектная очередь и карточка читают каноническую связь и показывают назначенного инженера, включая ещё не активированного пользователя.
- Источник-оракул: read-only legacy `fm_maintable.responsstroicontrol` и соответствующая строка legacy `users`; target seam: canonical Yii2 `legacy-import/run` через owner импорта identity и связи объекта.
- Release value: чистый стенд после `make import-legacy` сразу содержит объекты и достоверно связанных с ними инженеров, готовых к последующему приглашению владельцем.
- Не входят: автоматическая отправка приглашений, автоматическая активация или вход, сопоставление по ФИО, импорт произвольных legacy-пользователей, изменение инженера через экран объекта, перенос старых сессий/паролей и изменение кадрового импорта монтажников.

## Capabilities

### New Capabilities

- `identity/legacy-control-engineer-import`: импорт referenced legacy-инженеров как неактивных локальных пользователей, их устойчивое identity-сопоставление и последующая явная выдача приглашения администратором.
- `installation/legacy-control-engineer-assignment`: импорт и чтение канонической связи монтажного дела с инженером по legacy `responsstroicontrol` с идемпотентностью, provenance и fail-safe конфликтами.

### Modified Capabilities

- Нет.

## Impact

- Legacy snapshot и `legacy-import/run`, import application transaction и его итоговые счётчики.
- Канонические identity/access и installation-process migrations на актуальном schema frontier; `fm2_pilot_users`, роли/capabilities, legacy identity links и связь installation case → engineer.
- Yii2 object queue/card и административный справочник пользователей/flow генерации приглашения.
- Focused unit, DB, console import и authenticated HTTP acceptance tests; clean-stand bootstrap и повторный импорт.
- Внешние источники остаются read-only; email/legacy ID считаются данными источника, но пароль и invitation secret импортом не создаются.
